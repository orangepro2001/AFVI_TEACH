# 实时联机（Live Link）

相机合成工作室（`camera-gui.exe`）与教学程序（`teach-imgui.exe`）通过本机端口直接通信：工作室里画的缺陷在约 0.1 秒后就出现在教学程序的测试图里，**不需要保存任何图片文件**。需要留存时，由教学程序把它看到的图像和检出参数保存到文件夹，下次用「载入」读回。

两个程序只共享这份契约（`internal/link`），互不导入对方的代码：工作室是服务端，教学程序是客户端。

## 默认值

| 项目 | 默认 |
| --- | --- |
| 地址 | `127.0.0.1:47631`（只绑定回环，无认证） |
| 命令行 | `-link <地址>`（两个程序通用）；`-link off` 关闭 |
| 环境变量 | `AFVI_LINK`，命令行优先 |
| 只写端口号 | `-link 5000` 即 `127.0.0.1:5000` |
| 通配地址 | 工作室可监听 `0.0.0.0:端口`；教学程序遇到通配主机会改拨 `127.0.0.1` |
| 自测 | `-selftest` 默认不联机，显式给出 `-link` 才联机 |
| 默认保存位置 | `<exe 所在目录>\captures\<型号 id，/ 换成 ->`，工作室「输出」栏与教学程序「相机抓拍」路径框相同 |

工作室端口被占用时程序照常运行，「输出」栏的「实时联机」分组会显示原因。教学程序每 2 秒重拨一次，所以两个程序谁先启动都可以，工作室中途重启也会自动接上。

## 传输

TCP，每条消息 = 20 字节头 + JSON 部分 + 二进制部分（多字节整数均为大端）：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | 魔数 `AFVL` |
| 4 | 1 | 协议版本（当前 1，不同版本互相拒绝） |
| 5 | 1 | 消息类型 |
| 6 | 2 | 保留（0） |
| 8 | 4 | id：请求与应答配对，推送为 0 |
| 12 | 4 | JSON 长度（上限 64 MiB） |
| 16 | 4 | 二进制长度（上限 1 GiB） |

| 类型 | 名称 | 方向 | JSON | 二进制 |
| --- | --- | --- | --- | --- |
| 1 | hello | 双向，连接后各发一条 | `{"protocol":1,"role":"studio"\|"teach","app":"…","pid":N,"session":"…"}` | 无 |
| 2 | scene | 工作室 → 教学，推送（id 0） | `{"rev":N,"meta":{…snap.json 的内容，无 images…}}` | 无 |
| 3 | getFrame | 教学 → 工作室 | `{"rev":N,"channel":"red"\|"green"\|"blue","kind":"test"\|"good"\|"golden"}` | 无 |
| 4 | frame | 工作室 → 教学，应答 getFrame（同 id） | `{"rev":N,"channel":…,"kind":…,"width":W,"height":H,"enc":"raw"}` | W×H 字节 8 位灰度，行优先 |
| 5 | error | 应答 getFrame（同 id）或报告连接问题（id 0） | `{"code":"…","message":"…"}` | 无 |

- 两端连接后**都先写** hello，不互相等待；握手限时 5 秒。`session` 是工作室进程启动时随机生成的标识，修订号只在同一 session 内可比。
- 工作室收到 hello 后立即推送当前 scene（若已有发布），之后每次发布都推送；一连串快速发布在慢连接上会合并成只推最新一份。
- 未知的消息类型被忽略，未知的 JSON 字段被忽略，所以协议可以向后兼容地加字段。

### 修订与过期

scene 的 `rev` 在一个 session 内严格递增。getFrame 带上教学程序正在处理的 `rev`（0 表示"当前版本"）：

- 与工作室当前修订不同 → 错误码 `stale`，教学程序静默放弃，等待下一条 scene 推送再取；
- 渲染过程中工作室发布了新修订 → 同样 `stale`（渲染完成后再核对一次），不会把旧图当新图交付。

其他错误码：`no-scene`（还没有发布）、`bad-request`（未知通道或种类、请求格式错误、握手失败）、`render`（渲染失败）。

### 图像种类

| kind | 内容 | 谁需要 |
| --- | --- | --- |
| `test` | 带缺陷、带成像噪声的测试图 | 检出 |
| `good` | 不含缺陷的良品样本（噪声种子与测试图不同） | 学习区间 |
| `golden` | 同一光照下的干净渲染 | 仅"标准图 / 差异图"视图，按需才取 |

三种图都与 `camera.exe` 用同一份描述写出的 PNG **逐字节相同**（同一套渲染函数、同一份 `snap.Meta`）；联机的 scene 里没有图像，描述本身就是完整的配方。

## 工作室一侧

- 每帧检查场景指针与渲染修订，变化后等 120 ms 无新变化再发布，连续拖动时最迟 400 ms 发布一次；配方（型号 + 光照 + 虚拟良品 + 噪声 + 笔画）没变就不重复发布。
- 发布时把描述深拷贝进渲染器，之后的编辑不会改变已发布的修订。每个修订最多同时渲染 2 张，最近 4 张帧缓存在服务端；一次渲染同时得到测试图与标准图，用不到的那张留给紧接着的请求。
- 「输出」栏的「实时联机」分组显示监听地址、已连接的教学程序与当前修订；「保存抓拍」仍然可用，写法不变（交给 `camera.exe`）。

## 教学程序一侧

- 缺陷页左侧的「实时联机」分组：连接状态、「跟随相机工作室」复选框（默认勾选）、测试图来源（工作室实时 / 抓拍文件夹 / 本程序的本地仿真）。
- 跟随时，每出现新修订就采用它：只取像素，**不**同步工作室的光照、虚拟良品或笔画。检出照旧只看测试图与设计材质图，已学到的区间保留，所以改光照后过检 / 漏检依然看得见；要用新场景的良品样本重新学习，点 F1 里的「重新学习区间」。
- 工作室打开的型号与教学程序当前型号（或图像尺寸）不同时不采用，并给出"切换到该型号"按钮。
- 连接中断时保留最后一张图；取图失败 2 秒后自动重试；`stale` 不算失败。
- 「抓拍」「载入」或手动勾选「使用相机抓拍图像」会停止跟随（避免你选的文件被实时画面悄悄替换）；取消勾选「跟随相机工作室」回到本地仿真。

## 保存与读取

教学程序「相机抓拍」分组里，路径框默认是 `captures\<型号 id>`（用户改过后不再自动变）：

- **保存**：写入 `snap.json` 与三个通道的测试图 `red.png`… 和良品图 `red-good.png`…，以及 `inspect.json`（检出参数）。来源是实时画面时直接写已经收到的帧，其余通道向工作室再取；来源是本地仿真或已载入的抓拍时，用同一份描述让 `camera.exe` 渲染。
- **载入**：读入文件夹；其中有 `inspect.json` 且型号、尺寸相符时同时恢复检出参数（已学习的区间不再重新学习）。

### inspect.json（`afvi-inspect` v1）

```json
{
  "format": "afvi-inspect",
  "version": 1,
  "producer": "afvi-teach 1",
  "saved": "2026-10-19T07:50:00Z",
  "model": "FM1/25fbo015-15",
  "width": 5860,
  "height": 4020,
  "learnK": 5,
  "channels": {
    "red": {
      "learned": true,
      "params": {
        "materials": {
          "base":  {"enabled": false, "low": 0,  "high": 255, "size": 3, "minArea": 4, "localBackground": false},
          "sr":    {"enabled": true,  "low": 2,  "high": 30,  "size": 3, "minArea": 4, "localBackground": false},
          "open":  {"enabled": false, "low": 0,  "high": 255, "size": 3, "minArea": 4, "localBackground": false},
          "metal": {"enabled": true,  "low": 69, "high": 255, "size": 3, "minArea": 4, "localBackground": true}
        },
        "edgeMargin": 6,
        "backgroundRadius": 2
      }
    }
  }
}
```

- 材质按名字（`base`、`sr`、`open`、`metal`）存放，不依赖内部下标；每个通道（`red`、`green`、`blue`）一份，缺少的通道和字段保持当前值或库默认值，未知字段忽略。
- 读取时校验格式、版本与取值范围（区间、边缘余量、背景半径）；型号或尺寸不符的文件被忽略并提示。
- F1 检出参数窗口里也有「保存检出参数 / 载入检出参数」两个按钮，读写同一个文件。
- 文件只含检出参数，没有任何仿真信息（检出与仿真互不相识的约束不变）。

## 实现与测试

| 位置 | 内容 |
| --- | --- |
| `internal/link` | 协议、`Server`（工作室）、`Client`（教学）；只导入标准库与 `internal/snap` |
| `internal/inspect/paramsio.go` | `inspect.json` 的读写与校验（只用标准库） |
| `internal/app/live*.go`、`teach_save.go` | 两个程序里接入联机、跟随、保存的代码；只有这几个文件能导入 `internal/link` |

测试：`internal/link` 的 15 个测试（往返、过期、渲染中发布、各类错误、合并推送、缓存失效、多客户端、服务端关闭、取消、2048×1536 大帧、非联机对端、协议版本不符、成帧、导入限制）用 `-race` 也通过；`internal/app` 的无窗口测试用回环端口把一个工作室和一个教学程序接在一起（采用修订、画缺陷后教学程序随之变化、与工作室自身渲染及 `camera.exe` 的 PNG 逐字节相同、保存 / 载入往返、型号不符、断线重连、去抖）；自测在给出 `-link` 时多一个 `live` 步骤，与另一个进程里的真实工作室联机核对。
