# 角色、对位流程与相机默认错位

本文档说明教学程序（teach-imgui.exe）与相机合成工作室（camera-gui.exe）的用户角色、页面可见性、强制对位流程，以及 `camera.exe` 与内置仿真默认带有的轻微错位。日常操作步骤见 [USAGE.md](USAGE.md)。

## 角色与登录

程序有两种角色：

- **操作员（operator）**：只看到引导式的「对位」与「检测」两页，没有参数、表格和绘制工具。
- **管理员（admin）**：原来的完整工程界面（对位、对位试验台、缺陷检出 / 合成，以及机台配置、切换机台、重新扫描型号等）。

教学程序默认以操作员身份启动；相机合成工作室是管理员工具，启动时锁定在登录窗口，未登录时不显示任何页面。

登录入口是「文件 ▸ 管理员登录…」（操作员）与「文件 ▸ 注销」（管理员），工具栏右端也有用户名和按钮。内置账号：

| 用户 | 密码 | 角色 |
| --- | --- | --- |
| `admin` | `1` | 管理员 |
| `operator` | （空） | 操作员 |

用户名去掉首尾空格并忽略大小写。密码只比较 SHA-256 摘要（恒定时间比较），但内置账号只是划分两种界面用的便利手段，**不是安全边界**：exe 在本机运行且未签名，任何能运行程序的人都能绕过它。

注销时，教学程序回到操作员界面；工作室回到锁定状态，登录窗口不能取消，只能登录或退出程序。

## 页面表

页面按全局顺序注册，再按当前角色过滤（默认拒绝：没有绑定角色的页面不会显示）。隐藏的页面仍然保持自己的状态，但既不能切换过去也不会被绘制；机台配置对话框、切换机台与重新扫描型号这类管理员操作对操作员无效。

| 顺序 | 页面 id | 角色 | 程序 | 页签标题 |
| --- | --- | --- | --- | --- |
| 0 | `light` | 管理员 | 工作室 | 光照与 GV |
| 1 | `roi` | 管理员 | 教学程序 | 对位 |
| 1 | `op-align` | 操作员 | 教学程序 | 对位 |
| 2 | `align` | 管理员 | 教学程序 | 对位试验台 |
| 2 | `op-inspect` | 操作员 | 教学程序 | 检测 |
| 3 | `defect` | 管理员 | 教学程序 / 工作室 | 缺陷检出 / 缺陷合成 |

管理员的「对位」是工程视图：ROI 列表与逐 ROI 匹配表（名称、NCC、唯一性、找到与否 / 错误）、缩放 / 搜索半径 / 最小 NCC / 最小唯一性滑块、判定徽章与原因，以及设计图、原始抓拍、对齐后的图和叠加四种视图。原先基于合成错位的对齐页现在是「对位试验台」。

## 角色能力对照

| 功能 | 操作员 | 管理员 |
| --- | --- | --- |
| 对位页 | 引导版：大按钮、恢复默认框、状态徽章、设计 / 原始 / 对齐后的查看切换 | 工程版：再加逐 ROI 匹配表、参数滑块与四种视图 |
| 对位试验台 | 不可见 | 可见（合成错位实验，不参与真实抓拍的对位） |
| 检测 / 缺陷检出 | 引导版检测页：R/G/B、检测按钮、OK / NG 判定、简短缺陷列表 | 完整缺陷检出页：相机抓拍来源、F1 参数、学习区间、结果与探查 |
| 相机合成工作室 | 不可用（该程序只接受管理员） | 全部功能，包括输出与场景文件 |
| 机台配置、切换机台、重新扫描型号 | 无效 | 可用 |
| 悬浮工具面板 | 对位 / 检测页不显示 | 按页面能力提供 |

## 对位流程（操作员）

1. 启动教学程序，打开型号；「对位」页首先显示产品的**设计假想图**（底色黑、阻焊绿、金属黄）。
2. 在图上拖动绘制 ROI 框，拖动框内部移动它，Delete 删除选中的框；机台自带的 ROI 是起点，也可以按「恢复默认框」回到它们。
3. 按大按钮「确定对位」。状态徽章显示未对位 / 对位中 / 对位完成 OK / 对位失败（附一行原因）。
4. 转到「检测」页：选择 R/G/B 通道，按大按钮「检测」，页面给出大号 OK / NG 判定与简短的缺陷列表（材质、极性、大小），点击列表项可在视图中定位。没有参数、探查或学习按钮。

## 对位流程（管理员）

管理员在「对位」页做同样的强制对位，但能看到完整信息：逐 ROI 匹配表、匹配参数滑块、判定原因，以及设计图、原始抓拍、对齐后的图和叠加视图。ROI 或参数一旦改动，之前确认的对位即作废，需要重新按「确定对位」。「对位试验台」保留原来的合成错位实验（扭曲参数、真值核对、对齐后视图等），不参与真实抓拍的对位。

## 对位是强制的

确认对位之前，检测被阻止，页面会说明原因；确认之后，每一张抓拍都要先用这些 ROI 对齐，然后才进入检出。只有对齐后的 8 位灰度图和设计材质图会交给 `internal/inspect`。

- 对齐结果是**全分辨率的抓拍重采样到设计网格**上的图；没有有效像素的边缘用最近的有效像素复制，不留黑边。
- 编辑 ROI（绘制、移动、删除、恢复默认）会取消已确认的对位；换型号也会。
- 换通道、改光照、重新抓拍或收到新的联机修订会自动用已确认的 ROI 重新对齐，不需要再按「确定对位」。

## 相机默认错位与 `-aligned`

模拟相机默认不是正对的：`core.DefaultCaptureWarp()` 给抓拍加上平移 (14, -10) 像素、旋转 0.3°（缩放 1）。`camera.exe` 的默认场景和教学程序内置的仿真抓拍都用这个错位，所以不先对位就会在材质边缘产生误检。

`camera.exe -aligned` 让内置默认场景**原地**渲染（不套默认错位），输出的描述与旧版默认逐字节相同；它只作用于内置默认场景，和 `-in` 一起给出时被忽略。显式给出的 `-dx -dy -rot …` 仍然逐项覆盖当前配方，所以也能在 `-in` 上重新定位。

相机合成工作室自己的默认错位仍是「无」——绘制缺陷需要正对的图；「错位与翘起」的预设里新增了「典型错位（相机默认）」，一键套用同一组参数。

## 命令行 `-login`

两个程序都接受 `-login user:password`（在第一个冒号处分割）：

```powershell
.\bin\teach-imgui.exe -login admin:1
.\bin\camera-gui.exe -login admin:1
```

账号无效时在 stderr 报错并以退出码 2 结束；工作室只接受管理员登录。教学程序不带 `-login` 时以操作员启动，工作室不带时锁定在登录窗口。`-selftest` 会用 `admin` / `1` 自己登录，所以自测看到的仍是管理员页面。

## 局限

- 内置账号只用于区分两种界面，不是权限或安全机制；密码摘要存在程序里，exe 未签名，本机用户可以绕过。
- 对位使用与「对位试验台」相同的相似变换匹配；严重翘起、弯曲或大范围遮挡时可能对不上，此时状态是「对位失败」，检测保持阻止。
- 检出仍然只看对齐后的灰度图与设计材质图，对位质量直接决定材质边缘是否被误检。
