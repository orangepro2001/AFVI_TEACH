# Color AFVI Master Teach（原生版）

## 简介

本文档介绍 Color AFVI Master Teach 原生实现（teach-imgui）：Go + Dear ImGui（cimgui-go v1.6.1 / ImGui 1.93 WIP，GLFW + OpenGL3 后端），取代 teach-app 的 WebView2 外壳。teach-app 与 teach-core 仍保留在仓库中，作为规格说明与对照实现。

界面采用经典 Win32（"Windows Classic"）外观：凸起按钮、凹陷输入框、蚀刻分组框等 3D 立体边框，灰色面板底色，深蓝渐变对话框标题栏，属性表风格页签，以及真正的菜单栏、工具栏和多窗格状态栏（含尺寸手柄）。默认主题为经典浅灰（`light`），深色主题（`dark`）沿用同一套立体边框方案，只是换成深灰配色。实现分布在 `internal/app/theme.go`（调色板与样式）、`internal/app/win32.go`（`DrawEdge`、`Caption`、`HotText` 等立体边框原语）、`internal/app/widgets.go`（自绘按钮、`GroupBox`、`TabStrip` 等控件）与 `internal/app/app.go`（菜单栏 / 工具栏 / 页签 / 状态栏布局）。

## 构建

前提：

- Go 1.27
- MinGW-w64：`scoop install mingw`（scoop 不会创建 gcc shim，`build.ps1` 会自动把 `%USERPROFILE%\scoop\apps\mingw\current\bin` 加到 PATH 前面）

常用命令：

```powershell
.\scripts\build.ps1              # gofmt + go vet + 配置/核心测试 + 构建
.\scripts\build.ps1 -Selftest    # 构建后运行自测并解析 native-metrics.json
.\scripts\build.ps1 -Offline     # GOPROXY=off，使用已就绪的模块缓存离线构建
```

首次编译约 3 分钟（cgo 包装层），之后增量编译约 2 秒。静态链接后 exe 约 7 MB，只依赖系统 DLL（含 Win10+ 自带的 UCRT）。模块缓存就绪后可用 `GOPROXY=off` 离线构建。构建输出为 `bin\teach-imgui.exe`。

## 运行参数

| 参数 | 说明 |
| --- | --- |
| `-config <文件>` | 机台配置文件（afvi.toml）；默认按 `AFVI_CONFIG`、exe 同级、工作目录顺序查找 |
| `-machine <名称>` | 启动时激活的机台（不区分大小写） |
| `-ref <目录>` | reference 目录（包含 FM1/FM2/BM）；写入并激活模拟的 REFERENCE 机台 |
| `-theme dark\|light` | 界面主题（默认：配置文件，否则 `light`） |
| `-lang zh\|en\|ko` | 界面语言（默认：配置文件，否则 `zh`） |
| `-model FM1/25fbo015-15` | 启动时打开的型号 |
| `-selftest` | 自测模式：遍历所有页签、主题与语言，保存截图与指标后退出 |
| `-out <目录>` | 自测输出目录 |
| `-exitafter 12s` | 指定时长后自动关闭窗口 |

环境变量 `AFVI_CAMERA_EXE` 可指定 `camera.exe` 的路径；未设置时按教学程序 exe 同级、PATH 顺序查找。

配置文件查找顺序：`-config <文件>` → 环境变量 `AFVI_CONFIG` → exe 同级的 `afvi.toml` → 工作目录的 `afvi.toml`。没有任何配置文件时，应用按旧的 reference 查找顺序（`-ref` → 环境变量 `AFVI_REFERENCE_DIR` → exe 目录及向上 5 级的 `reference/` → 工作目录及向上 5 级的 `reference/`）模拟一台名为 `REFERENCE`（地址 `localhost`）的机台。

## 机台配置（afvi.toml）

`afvi.toml` 按机台记录 `name`、`address` 以及三个数据根目录 `fm1`、`fm2`、`bm`（每个目录内含 `PxRepository`，可选含 `PxInventory/INSPECT_SPEC`）。相对路径相对 `afvi.toml` 所在目录解析；Windows 路径建议用 TOML 单引号字面量字符串（反斜杠不被转义）。顶层键为 `active`、`theme`、`lang`。示例见 `configs/afvi.example.toml`（REFERENCE 加两台远程示例机台），真正的 `afvi.toml` 已被 git 忽略。

- **视图**：主题 ▸ 经典 / 深色、语言 ▸ 中文 / English / 한국어、适应窗口
- **帮助**：关于…

## 机台配置对话框

通过「文件 ▸ 机台配置…」或工具栏的 `…` 按钮打开：左侧为机台列表，带 [添加] / [删除] / [复制]；右侧为名称、地址字段，以及 FM1/FM2/BM 路径字段，每条路径带状态（`正常 — N 个型号`、`路径不存在`、`缺少 PxRepository`、`未设置`），由 [检查] 刷新。[确定] 保存 `afvi.toml` 并切换到所选机台（重新扫描型号），[应用] 保存但保持对话框打开，[取消] 放弃修改。

## 操作

- 滚轮：以光标为中心缩放
- Shift + 鼠标左键点击：放大（×1.5，以光标为中心）；Shift + 鼠标右键点击：缩小（÷1.5，以光标为中心）
- 中键 / 右键拖动：平移
- 双击：适应窗口（画框工具绘制过程中不会触发）
- 悬浮工具面板：视图右侧的 Photoshop 风格工具面板，含点选、矩形框、椭圆框、多边形框与专注按钮；当前页面不支持的工具会变灰并忽略点击，再次点击已激活的工具即回到平移。光照页只支持矩形框（GV 测量框，始终激活）；对齐页支持点选（选择/移动 ROI）与矩形框（新建 ROI / 遮挡）；缺陷页四个工具都支持（选择工具）
- 专注模式：点击面板上的专注按钮、按 F11 或选择「视图 ▸ 专注模式」，隐藏左右两侧面板让中央图像铺满窗口，便于细看；F1 参数窗口与选中的不良窗口仍可正常使用，双击适应窗口的行为不变
- 左键：当前页工具
  - 光照页：拖框测量 GV
  - 对齐页：新建 ROI / 遮挡，选择移动，Delete 删除选中 ROI
  - 缺陷页：画点 / 线 / 块 / 异物 / 污染，探查
  - 缺陷页画框工具：矩形 / 椭圆 / 钢笔（类 Photoshop 钢笔：左键依次添加顶点，右键闭合多边形，Esc 取消，Backspace 撤销上一个顶点），可选择"亮/暗"极性；幅度、边缘轮廓、柔和度沿用左侧对应设置；画出的框成为不良（矩形/椭圆/多边形）并出现在笔画列表中
  - 缺陷页虚拟产品：左侧第二个分组（紧跟渲染通道之后）。真实板面不可能完全均匀——约 2 µm/像素下再好的表面工艺也有起伏，而加载的 MEDIAN 是多块良品的中值、过于平滑；加载型号时会把一份确定性的、带种子的空间相关变化（多尺度值噪声 + 逐像素颗粒，按材质各自的相对 σ）烘焙进光照场景，因此光照 / 对齐 / 缺陷三页渲染的都是略微不均匀的"真实"良品。控件：启用虚拟良品、纹理强度 0–3（变化幅度）、纹理种子 1–9999、相关长度倍率 0.25–4、换一块板（换随机种子）、恢复默认；任何改动都会即时重新烘焙场景。注意光照页自己的"纹理强度"滑块（0–1）会整体缩放纹理（含这份变化），把它设为 0 即得到理想均匀样品。默认种子 1、强度 1；参考型号上 SR 纹理的 RMS 变化约 0.118（相对值），5860×4020 生成一次约 0.25 s。`Scene.Stats`（逐材质 MEDIAN 统计）仍是原图的统计；Inspect 依旧只看测试图与设计材质图
  - 缺陷页默认不良：每次加载型号时缺陷页会自动加入约 10 个很小的亮点（数量 10、种子 7）：半径 1.5–3 像素、ΔGV 45–90（绝对）、高斯轮廓、柔和度 0.3，只放在 SR 内，且要求中心周围 `边缘忽略 + ceil(半径) + 3` 像素的整个窗口都是 SR（因此绝不会落在 Inspect 忽略的边缘带里）。它们是普通笔画（标记为 auto），出现在笔画列表中，可被选中、编辑、删除。参考型号实测（自测 `defaults-detected`）：10 条笔画，5860×4020 图中只有 175 个像素与干净渲染不同（肉眼不可见），自动学习后 10 个全部被 Inspect 检出，另有 1 个自然过检（良品并非绝对干净），学到的 SR 区间为 [2,30]。控件：默认不良数量 0–50、默认不良种子 1–9999、重新生成默认不良、移除默认不良，以及复选框"显示模拟笔画轮廓"（用至少 4 像素的标记画出笔画轮廓；关掉即可对学生隐藏答案，让他们必须通过 Inspect 找不良；选中高亮仍然可见）
  - 缺陷页选择与调参：悬浮工具面板的点选 / 矩形框 / 椭圆框 / 多边形框用于选择 GV 笔画。点选 = 单击选中最近的笔画（容差 6 屏幕像素，距离相同时取更小的那个；Ctrl+单击加入/移出选择；单击后继续拖动仍是平移）；矩形 / 椭圆 / 多边形框（拖动；多边形左键添加顶点、右键闭合；Esc 取消、Backspace 撤销上一个顶点）选中包围盒中心落在框内的所有笔画（Ctrl+拖动为加入而非替换；没有真正拖动的单击等同点选）。Delete 删除选中的笔画，Esc 清空选择。左侧面板武装的笔刷 / 画框放置工具优先，用完后选择工具恢复。选中的笔画以黄色高亮并保证最小屏幕尺寸（7 像素圆环 / 14 像素方框），适应窗口下 2 像素的不良也看得见；笔画列表给选中行加"● "前缀。浮动"选中的不良"窗口（选择非空时出现，`x` 清空选择）对全部选中笔画生效：更隐蔽（幅度 ×0.8、半径 ×0.9）与更清晰（幅度 ×1.25、半径 ×1.1）快捷按钮（目标模式的笔画保持目标值不变）、删除、取消选择、类型（亮/暗）、幅度模式（绝对/相对/目标）与跟随第一个选中笔画的数值滑块、半径、柔和度、颗粒、边缘轮廓、启用。窗口还显示"检出：N / M 个已被 Inspect 检出"——这只是 UI 层把报告框与笔画包围盒做比较的显示（`strokeDetected`），`internal/inspect` 依旧对笔画一无所知。自测 `select-edit`：ΔGV 80 的亮点被检出，执行"更隐蔽"（ΔGV 4、半径 1）后不再被检出，未选中的邻居仍被检出
  - 缺陷页不良颜色：勾选"按颜色模拟"后，新画的不良带有 RGB 颜色（R、G、B 滑块 0–1 与七个预设：红、绿、蓝、白、黄、青、品红，列表中显示 RGB 后缀，视图中轮廓用该颜色显示）；渲染通道（Red/Green/Blue）下画面仍是黑白灰度，不良在某通道中的亮度变化 = 幅度 × 该通道的颜色分量（例如纯红不良只在 Red 通道可见，白色不良在三个通道都可见）；颜色设置只作用于之后新画的不良，随机批量生成也使用当前颜色
  - 缺陷页检出参数：按 F1 唤出/关闭的浮动窗口（可拖动、可滚动，调整时检出结果实时刷新；Esc 或标题栏 × 关闭），左侧只保留"检出参数…（F1）"按钮与提示。窗口内按相机通道（Red/Green/Blue）各有一套参数：学习系数 k（0.5–12，默认 5）、"重新学习区间"与"恢复默认并重学"按钮、边缘忽略（像素）0–64（默认 6，三个通道共用，修改后会重新学习区间，下方给出说明与被忽略的像素数）、局部背景半径（像素）0–16（默认 2，三个通道共用，修改后会重新学习区间），以及 metal / sr / open / base 每个材质一节的启用、下限 Low、上限 High、分组尺寸 Size、最小面积 MinArea 与当前图统计
  - 缺陷页局部背景（BackgroundRadius，0–16，默认 2，0 为关闭）：每个材质有"使用局部背景"开关，默认只对金属开启。0 = 关闭，区间直接作用于原始 GV；大于 0 时，勾选了该开关的材质先减去同材质 (2r+1)² 邻域的中位数（局部背景）再套用区间，金属这类亮度不均匀的材质不会整块报成巨大缺陷，过检时表现为零散的小点；代价是中位数会跟随有清晰边缘的平台，只检出比窗口小的局部异常，大块平整的缺陷会被当作背景（例如 SR 上画的 7×7、+80 的方块完全检不出），所以 SR 等亮度单峰的材质默认保持全局区间。统计表里的标准差与范围是扣除局部背景后的值，缺陷的峰值/均值 GV 仍是原始灰度；修改半径或开关都会重新学习区间
  - 缺陷页检出原理：只看测试图的亮度，按设计材质图逐材质判断——某材质的像素落在可接受区间 [Low, High] 之外就被标记（高于 High 为过亮，低于 Low 为过暗）；良品亮度越界也会被标记（过检），区间过宽则会漏检。Size 把每个被标记像素膨胀 Size/2 后把相邻分组并成一个缺陷（结果里的"碎块数"即合并的碎块数），MinArea 丢弃标记像素数不足的分组；过亮/过暗与不同材质之间不会合并。区间由良品样本学习得到：首次显示某型号/通道时（或按"重新学习区间"）渲染一张不含不良的良品样本（噪声种子不同），每个启用材质取 Low/High = 均值 ∓ k·σ；改变光照不会自动重学，因此过检/漏检会显现出来
  - 缺陷页边缘忽略（Margine）：与不同材质的像素的切比雪夫距离不超过"边缘忽略"（0–64 像素，默认 6）的像素会被忽略——不计入逐材质统计、不参与学习、永不被标记、探查时也不统计。报告里的"被忽略的边缘像素"与探查里的"框内被边缘忽略的像素"给出被忽略的数量。原因：参考型号的 SR 层约有 8000 个亮度 28–61 的像素（SR 均值 15），它们是 SR/Metal 交界处被模糊的过渡像素；没有边缘忽略时良品会报出 139 个过检，设为 6 后只剩 11 个（10 个真实 + 1 个）。自测：`edge-margin-off` 139 个缺陷，`edge-margin-on` 11 个
  - 缺陷页结果：检出数、因 MinArea 滤除的分组数、越界像素总数；逐材质统计表（材质、像素、均值、标准差、最小、最大、区间、过亮、过暗）；缺陷表（材质、极性、面积、宽×高、峰值 GV、超出量、均值 GV、碎块数，最多显示面积最大的前 500 个，点击某行视图居中）。视图上的缺陷框：橙色为过亮、蓝色为过暗，并带"材质 面积"标签
  - 缺陷页探查：拖框后按材质显示像素数、均值、最小/最大、区间与过亮/过暗计数，并给出通俗解释（全部落在区间内 → 没有标记，区间过宽会漏检；有标记但分组小于 MinArea → 被丢弃；否则给出框内缺陷数）
  - 缺陷页的标准图 / 差异图只是仿真的显示辅助，检出本身从不接收标准图
- 菜单栏：文件（机台配置…、重新扫描型号、退出）、视图（主题、语言、适应窗口）、帮助（关于…）
- 工具栏：机台下拉框 + `…` 按钮、型号下拉框、加载状态
- 页签：切换光照 / 对齐 / 缺陷页，切换均不重载

## 相机抓拍（Snap）

缺陷页左侧面板的"相机抓拍"分组（紧跟渲染通道分组之后）把测试图换成独立相机程序 `camera.exe` 的"实拍"图：

- 勾选"使用相机抓拍图像"后，按钮 **Snap** 把当前场景（启用的笔画、虚拟良品、光照、噪声）写成描述文件，运行 `camera.exe`，读回 PNG 并检出；文本框 + **Load** 读取已有抓拍文件夹或描述文件，并导入其中的笔画与噪声。
- 抓拍后又编辑过（改笔画、光照、噪声等）会显示过期警告：需要重新 Snap，在此之前仍显示已抓拍的图像。
- 切换渲染通道时按需向 `camera.exe` 索取缺失的通道；取消勾选即回到进程内仿真。
- 标准图 / 差异图仍是本地干净渲染；检出依旧只接收测试图与设计材质图。
- 临时抓拍文件夹在被替换、重置或退出时删除。

手工运行相机程序（Linux 或 Windows 均可，纯 Go）：

```bash
bin/camera -ref reference -list
bin/camera -ref reference -model FM1/25fbo015-15 -channels red,green,blue -good -out capture/
bin/camera -in capture/snap.json -out capture2/ -channels blue
bin/camera -info capture/snap.json
```

直接运行 `bin/camera`（不带 `-model` 与 `-in`）会使用当前机台的第一个型号，渲染红色通道并写入 `snap-out/`；它是命令行程序，在资源管理器里双击会一闪而过，请在终端里运行。

## 目录结构

- `cmd/teach-imgui/main.go`：入口
- `internal/app/run.go`：命令行参数、字体、窗口、主循环
- `internal/core/`：仿真（teach-core 的 Go 移植：gray、rng、light、warp、align、defect 涂抹与渲染，以及虚拟良品 `product.go` 与笔画几何 `strokegeom.go`）
- `internal/inspect/`：检出算法（只看测试图与设计材质图，含单元测试与隔离测试）
- `internal/config/`：纯 Go 的 TOML 子集配置包（含测试：`go test ./internal/config/...`）
- `internal/model/`：模型扫描与加载（纯 Go，含 `modeltest` 合成参考树）
- `internal/snap/`：抓拍文件格式（`snap.json` + 灰度 PNG，仅标准库与 core）
- `internal/camera/`：相机渲染与命令行（纯 Go，无 cgo）
- `cmd/camera/main.go`：相机模拟程序入口
- `internal/app/app.go`：Panel 接口、共享状态、布局（菜单栏 / 工具栏 / 页签 / 状态栏）
- `internal/app/win32.go`：Win32 立体边框原语（`DrawEdge`、`Caption`、`HotText` 等）

## 已知限制

- 纹理固定线性过滤，高倍放大像素会被插值。
- 60 fps 持续重绘（空闲约占单核 3.4%）。
- 字体取自 `C:\Windows\Fonts`（tahoma / msyh / malgun），仅 Windows。
- 未做高 DPI 缩放适配。
- 检出是教学用的简化亮度区间算法（Metal / SR 各一个区间；真实产品的 Space、Open 等分层与 Margine、Offset 等机台参数未模拟），成像噪声也是近似。
- 检出的边缘忽略（Margine）是单一全局像素数；虚拟良品是统计意义上的非均匀（多尺度噪声 + 颗粒），不模拟真实的划痕、氧化、批次差异；默认不良只放在 SR 内部亮点；选择工具只选 GV 笔画（异物/污染笔画不可选）。
- 自测的鼠标交互在视图层注入，不经过 GLFW 真实输入。
