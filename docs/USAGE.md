# Color AFVI Master Teach（原生版）

## 简介

本文档介绍 Color AFVI Master Teach 原生实现：Go + Dear ImGui（cimgui-go v1.6.1 / ImGui 1.93 WIP，GLFW + OpenGL3 后端），取代 teach-app 的 WebView2 外壳。同一个模块构建两个 GUI 程序——教学程序 **teach-imgui.exe**（操作员的对位与检测页；管理员登录后还有对位试验台与缺陷检出页）与相机合成工作室 **camera-gui.exe**（光照与 GV 页、缺陷合成页，camera.exe 的 GUI 前端，启动时锁定在管理员登录之后）——以及命令行相机程序 **camera.exe**。teach-app 与 teach-core 仍保留在仓库中，作为规格说明与对照实现。

界面采用经典 Win32（"Windows Classic"）外观：凸起按钮、凹陷输入框、蚀刻分组框等 3D 立体边框，灰色面板底色，深蓝渐变对话框标题栏，属性表风格页签，以及真正的菜单栏、工具栏和多窗格状态栏（含尺寸手柄）。默认主题为经典浅灰（`light`），深色主题（`dark`）沿用同一套立体边框方案，只是换成深灰配色。实现分布在 `internal/app/theme.go`（调色板与样式）、`internal/app/win32.go`（`DrawEdge`、`Caption`、`HotText` 等立体边框原语）、`internal/app/widgets.go`（自绘按钮、`GroupBox`、`TabStrip` 等控件）与 `internal/app/app.go`（菜单栏 / 工具栏 / 页签 / 状态栏布局）。

## 安装

拿到 `AFVI-Teach-Setup-<版本>.exe` 的用户直接双击即可：向导里选安装位置（默认 `%LOCALAPPDATA%\Programs\AFVI Teach`，每用户安装，不需要管理员权限）、是否创建开始菜单 / 桌面快捷方式、是否把安装文件夹加入 PATH（之后可在命令行直接运行 `camera.exe`）。装好的程序有教学程序、相机合成工作室、`camera.exe` 与文档；`afvi.toml` 和相机输出（`captures`）写在安装文件夹里，卸载时默认保留（`uninstall.exe -uninstall -purge` 一并删除）。没有随包带机台数据时，首次使用要按 [REFERENCE_SETUP.md](REFERENCE_SETUP.md) 放置 `reference` 或设置数据路径。静默安装、卸载参数和如何生成安装包见 [BUILD.md](BUILD.md)。

## 构建

前提：

- Go 1.27
- MinGW-w64：`scoop install mingw`（scoop 不会创建 gcc shim，`build.ps1` 会自动把 `%USERPROFILE%\scoop\apps\mingw\current\bin` 加到 PATH 前面）

常用命令：

```powershell
.\scripts\build.ps1              # gofmt + go vet + 配置/核心测试 + 构建 + 安装包（dist\AFVI-Teach-Setup-<版本>.exe）
.\scripts\build.ps1 -Selftest    # 构建后运行自测并解析 native-metrics.json
.\scripts\build.ps1 -Offline     # GOPROXY=off，使用已就绪的模块缓存离线构建
.\scripts\build.ps1 -NoInstaller # 只构建程序，不生成安装包（-Version / -Reference 见 BUILD.md）
```

首次编译约 3 分钟（cgo 包装层），之后增量编译约 2 秒。静态链接后 exe 约 10 MB，只依赖系统 DLL（含 Win10+ 自带的 UCRT）。模块缓存就绪后可用 `GOPROXY=off` 离线构建。构建输出为 `bin\teach-imgui.exe`。

## 运行参数

| 参数 | 说明 |
| --- | --- |
| `-config <文件>` | 机台配置文件（afvi.toml）；默认按 `AFVI_CONFIG`、exe 同级、工作目录顺序查找 |
| `-machine <名称>` | 启动时激活的机台（不区分大小写） |
| `-ref <目录>` | reference 目录（包含 FM1/FM2/BM）；写入并激活模拟的 REFERENCE 机台 |
| `-theme dark\|light` | 界面主题（默认：配置文件，否则 `light`） |
| `-lang zh\|en\|ko` | 界面语言（默认：配置文件，否则 `zh`） |
| `-model FM1/25fbo015-15` | 启动时打开的型号 |
| `-fontsize <10-28>` | 界面字号（像素，默认 16；布局常量按字号缩放） |
| `-link <地址>` | 实时联机地址：工作室监听它，教学程序拨它；默认 `127.0.0.1:47631`；只写端口号等于 `127.0.0.1:<端口>`；`off` 关闭（见 [LINK.md](LINK.md)） |
| `-login user:password` | 启动时登录（在第一个冒号处分割）：`admin:1` 进管理员界面，`operator:` 进操作员界面；工作室只接受管理员；无效时 stderr 报错、退出码 2（见 [ROLES.md](ROLES.md)） |
| `-selftest` | 自测模式：遍历所有页签、主题与语言，保存截图与指标后退出 |
| `-out <目录>` | 自测输出目录 |
| `-exitafter 12s` | 指定时长后自动关闭窗口 |

环境变量 `AFVI_CAMERA_EXE` 可指定 `camera.exe` 的路径；未设置时按教学程序 exe 同级、PATH 顺序查找。环境变量 `AFVI_LINK` 等价于 `-link`（命令行优先）。`-selftest` 默认不联机，显式给出 `-link` 才联机。

配置文件查找顺序：`-config <文件>` → 环境变量 `AFVI_CONFIG` → exe 同级的 `afvi.toml` → 工作目录的 `afvi.toml`。没有任何配置文件时，应用按旧的 reference 查找顺序（`-ref` → 环境变量 `AFVI_REFERENCE_DIR` → exe 目录及向上 5 级的 `reference/` → 工作目录及向上 5 级的 `reference/`）模拟一台名为 `REFERENCE`（地址 `localhost`）的机台。

## 操作员工作流

教学程序默认以操作员身份启动，只显示两页：

1. **启动**：打开程序，选择型号；必要时先让相机工作室运行，或用「相机抓拍」准备好测试图（这两项由管理员配置）。
2. **对位**：「对位」页先显示产品的设计假想图（底色黑、阻焊绿、金属黄）。拖动绘制 ROI 框、拖动框内部移动它、Delete 删除选中的框；机台自带的框是起点，按「恢复默认框」可回到它们。
3. **确定对位**：按大按钮「确定对位」。状态徽章给出未对位 / 对位中 / 对位完成 OK / 对位失败（附一行原因）。没有确认对位之前不能检测。
4. **检测**：切到「检测」页，选择 R/G/B 通道，按大按钮「检测」，页面给出大号 OK / NG 判定和简短的缺陷列表（材质、极性、大小），点击列表项可在视图中定位。这一页没有参数、探查、学习或图像来源控制。

之后每次换抓拍（实时联机的新修订、重新 Snap、载入抓拍、载入图像）都会自动用已确认的 ROI 重新对齐；编辑 ROI 或换型号则要重新「确定对位」。完整流程见 [ROLES.md](ROLES.md)。

## 管理员登录

「文件 ▸ 管理员登录…」（操作员）或「文件 ▸ 注销」（管理员）切换界面，工具栏右端也有用户名与按钮。内置账号：`admin` / `1`（管理员），`operator` / 空密码（操作员）。相机合成工作室是管理员工具，启动时锁定在登录窗口，未登录不显示页面，也不允许取消。密码只以 SHA-256 摘要比较；这套账号只是分开两种界面，不是安全边界（exe 在本机运行且未签名）。也可以用 `-login user:password` 在启动时登录，详见 [ROLES.md](ROLES.md)。

管理员界面是原来的完整工程：对位（工程视图，含匹配表、参数滑块与四种视图）、对位试验台（原来的合成错位对齐页）、缺陷检出页，以及机台配置、切换机台、重新扫描型号等操作；这些管理员操作对操作员无效。

## 机台配置（afvi.toml）

`afvi.toml` 按机台记录 `name`、`address` 以及三个数据根目录 `fm1`、`fm2`、`bm`（每个目录内含 `PxRepository`，可选含 `PxInventory/INSPECT_SPEC`）。相对路径相对 `afvi.toml` 所在目录解析；Windows 路径建议用 TOML 单引号字面量字符串（反斜杠不被转义）。顶层键为 `active`、`theme`、`lang`。示例见 `configs/afvi.example.toml`（REFERENCE 加两台远程示例机台），真正的 `afvi.toml` 已被 git 忽略。

## 菜单

- **文件**：管理员登录…（操作员）/ 注销（管理员）、机台配置…、重新扫描型号、退出
- **视图**：主题 ▸ 经典 / 深色、语言 ▸ 中文 / English / 한국어、适应窗口
- **帮助**：关于…

原先工具栏上的主题 / 语言下拉已移入「视图」菜单。工具栏保留：机台下拉框 + `…` 按钮（打开机台配置）+ 型号下拉框 + 加载状态，右端是用户名与登录 / 注销按钮。操作员没有机台下拉框和配置按钮，机台配置、切换机台与重新扫描对操作员无效。

## 机台配置对话框

通过「文件 ▸ 机台配置…」或工具栏的 `…` 按钮打开：左侧为机台列表，带 [添加] / [删除] / [复制]；右侧为名称、地址字段，以及 FM1/FM2/BM 路径字段，每条路径带状态（`正常 — N 个型号`、`路径不存在`、`缺少 PxRepository`、`未设置`），由 [检查] 刷新。[确定] 保存 `afvi.toml` 并切换到所选机台（重新扫描型号），[应用] 保存但保持对话框打开，[取消] 放弃修改。

## 操作

- 滚轮：以光标为中心缩放
- Shift + 鼠标左键点击：放大（×1.5，以光标为中心）；Shift + 鼠标右键点击：缩小（÷1.5，以光标为中心）
- 中键 / 右键拖动：平移
- 双击：适应窗口（画框工具绘制过程中不会触发）
- 悬浮工具面板：视图右侧的 Photoshop 风格工具面板，含点选、矩形框、椭圆框、多边形框与专注按钮；当前页面不支持的工具会变灰并忽略点击，再次点击已激活的工具即回到平移。光照页只支持矩形框（GV 测量框，始终激活）；对位试验台支持点选（选择/移动 ROI）与矩形框（新建 ROI / 遮挡）；缺陷页四个工具都支持（选择工具）；操作员的「对位」「检测」页不使用悬浮工具面板
- 专注模式：点击面板上的专注按钮、按 F11 或选择「视图 ▸ 专注模式」，隐藏左右两侧面板让中央图像铺满窗口，便于细看；F1 参数窗口与选中的不良窗口仍可正常使用，双击适应窗口的行为不变
- 左键：当前页工具
  - 光照页：拖框测量 GV
  - 对位页（管理员「对位」/ 操作员「对位」）：在产品的设计假想图上拖出新 ROI、拖动框内部移动、Delete 删除选中的框；按「确定对位」后才允许检测，改 ROI 或换型号后要重新确认。管理员版本另有逐 ROI 匹配表、匹配参数滑块与设计 / 原始 / 对齐后 / 叠加四种视图；操作员版本只有大按钮与状态徽章（见 [ROLES.md](ROLES.md)）
  - 对位试验台（管理员，原来的对齐页，基于合成错位）：新建 ROI / 遮挡，选择移动，Delete 删除选中 ROI。视图默认是叠加图（模板红、输入青），「模板图」下拉选 ROI 模板的来源：设计假想图（默认，只由设计的 Metal/SR/Open 材质层生成并先配准到 MEDIAN，没有真实纹理，只能靠形状匹配，随手画在无特征处的 ROI 会定位不到或判人工确认）或与源图相同（旧，模板与输入是同一张图，任何 ROI 都完美匹配，仅作对照），输入始终是扭曲后的真实图，「全图灰度差」与「对齐后局部残余位移」以扭曲前的真实原图为参照，不用假想图；每个 ROI 画出设计位置（灰虚线）、真值位置（青虚线）、对齐结果（实线，颜色 = 真值误差）、匹配点与位移向量；扭曲参数分为「错位（位置）」（含无 / 轻微错位 / 严重错位 / 翘起预设）、「翘起与形变」（翘起 X/Y 透视倾斜、弯曲、剪切）与默认折叠的「成像（光度）」；右侧判定区有大号 OK / MANUAL / NG 横幅、「与真值核对」（判定正确 / 漏判 / 误判 / 偏严 / 保守）、「设定 / 测得 / 差」表和带着色的各 ROI 结果（NCC、唯一性、残差、匹配误差、对齐误差、状态；表下方「逐个 ROI 诊断」说明外点 / 未定位的原因，判定原因点名具体 ROI），长度统一为全分辨率像素；匹配参数含「最小重叠」（默认 0.9，窗口伸出图像时只用图内部分匹配，1 = 必须完整在图内），过期按输入逐项比较判定；视图下拉另有「对齐后（算法结果）/ 对齐后叠加 / 对齐后差异」，把输入图按算法拟合出的变换（不是设定的错位参数）重采样到模板网格，判定区给出「全图灰度差 对齐前→后」和「对齐后局部残余位移 最大 / 均方根」，「放大到最大残余处」按钮缩放到 4 倍并定位到差得最多的窗口
  - 缺陷页：画点 / 线 / 块 / 异物 / 污染，探查
  - 缺陷页画框工具：矩形 / 椭圆 / 钢笔（类 Photoshop 钢笔：左键依次添加顶点，右键闭合多边形，Esc 取消，Backspace 撤销上一个顶点），可选择"亮/暗"极性；幅度、边缘轮廓、柔和度沿用左侧对应设置；画出的框成为不良（矩形/椭圆/多边形）并出现在笔画列表中
  - 缺陷页虚拟产品：左侧第二个分组（紧跟渲染通道之后）。真实板面不可能完全均匀——约 2 µm/像素下再好的表面工艺也有起伏，而加载的 MEDIAN 是多块良品的中值、过于平滑；加载型号时会把一份确定性的、带种子的空间相关变化（多尺度值噪声 + 逐像素颗粒，按材质各自的相对 σ）烘焙进光照场景，因此光照 / 对齐 / 缺陷三页渲染的都是略微不均匀的"真实"良品。控件：启用虚拟良品、纹理强度 0–3（变化幅度）、纹理种子 1–9999、相关长度倍率 0.25–4、换一块板（换随机种子）、恢复默认；任何改动都会即时重新烘焙场景。注意光照页自己的"纹理强度"滑块（0–1）会整体缩放纹理（含这份变化），把它设为 0 即得到理想均匀样品。默认种子 1、强度 1；参考型号上 SR 纹理的 RMS 变化约 0.118（相对值），5860×4020 生成一次约 0.25 s。`Scene.Stats`（逐材质 MEDIAN 统计）仍是原图的统计；Inspect 依旧只看测试图与设计材质图
  - 缺陷页默认不良：每次加载型号时缺陷页会自动加入约 10 个很小的亮点（数量 10、种子 7）：半径 1.5–3 像素、ΔGV 45–90（绝对）、高斯轮廓、柔和度 0.3，只放在 SR 内，且要求中心周围 `边缘忽略 + ceil(半径) + 3` 像素的整个窗口都是 SR（因此绝不会落在 Inspect 忽略的边缘带里）。它们是普通笔画（标记为 auto），出现在笔画列表中，可被选中、编辑、删除。参考型号实测（自测 `defaults-detected`）：10 条笔画，5860×4020 图中只有 175 个像素与干净渲染不同（肉眼不可见），自动学习后 10 个全部被 Inspect 检出，另有 1 个自然过检（良品并非绝对干净），学到的 SR 区间为 [2,30]。控件：默认不良数量 0–50、默认不良种子 1–9999、重新生成默认不良、移除默认不良，以及复选框"显示模拟笔画轮廓"（用至少 4 像素的标记画出笔画轮廓；关掉即可对学生隐藏答案，让他们必须通过 Inspect 找不良；选中高亮仍然可见）
  - 缺陷页选择与调参：悬浮工具面板的点选 / 矩形框 / 椭圆框 / 多边形框用于选择 GV 笔画。点选 = 单击选中最近的笔画（容差 6 屏幕像素，距离相同时取更小的那个；Ctrl+单击加入/移出选择；单击后继续拖动仍是平移）；矩形 / 椭圆 / 多边形框（拖动；多边形左键添加顶点、右键闭合；Esc 取消、Backspace 撤销上一个顶点）选中包围盒中心落在框内的所有笔画（Ctrl+拖动为加入而非替换；没有真正拖动的单击等同点选）。Delete 删除选中的笔画，Esc 清空选择。左侧面板武装的笔刷 / 画框放置工具优先，用完后选择工具恢复。选中的笔画以黄色高亮并保证最小屏幕尺寸（7 像素圆环 / 14 像素方框），适应窗口下 2 像素的不良也看得见；笔画列表给选中行加"● "前缀。浮动"选中的不良"窗口（选择非空时出现，`x` 清空选择）对全部选中笔画生效：更隐蔽（幅度 ×0.8、半径 ×0.9）与更清晰（幅度 ×1.25、半径 ×1.1）快捷按钮（目标模式的笔画保持目标值不变）、删除、取消选择、类型（亮/暗）、幅度模式（绝对/相对/目标）与跟随第一个选中笔画的数值滑块、半径、柔和度、颗粒、边缘轮廓、启用。窗口还显示"检出：N / M 个已被 Inspect 检出"——这只是 UI 层把报告框与笔画包围盒做比较的显示（`strokeDetected`），`internal/inspect` 依旧对笔画一无所知。自测 `select-edit`：ΔGV 80 的亮点被检出，执行"更隐蔽"（ΔGV 4、半径 1）后不再被检出，未选中的邻居仍被检出
  - 缺陷页不良颜色：勾选"按颜色模拟"后，新画的不良带有 RGB 颜色（R、G、B 滑块 0–1 与七个预设：红、绿、蓝、白、黄、青、品红，列表中显示 RGB 后缀，视图中轮廓用该颜色显示）；渲染通道（Red/Green/Blue）下画面仍是黑白灰度，不良在某通道中的亮度变化 = 幅度 × 该通道的颜色分量（例如纯红不良只在 Red 通道可见，白色不良在三个通道都可见）；颜色设置只作用于之后新画的不良，随机批量生成也使用当前颜色
  - 缺陷页检出参数：按 F1 唤出/关闭的浮动窗口（可拖动、可滚动，调整时检出结果实时刷新；Esc 或标题栏 × 关闭），左侧只保留"检出参数…（F1）"按钮与提示。窗口内按相机通道（Red/Green/Blue）各有一套参数：学习系数 k（0.5–12，默认 5）、"重新学习区间"与"恢复默认并重学"按钮、边缘忽略（像素）0–64（默认 6，三个通道共用，修改后会重新学习区间，下方给出说明与被忽略的像素数）、局部背景半径（像素）0–16（默认 2，三个通道共用，修改后会重新学习区间），以及 metal / sr / open / base 每个材质一节的启用、下限 Low、上限 High、连续像素数 Size、最小面积 MinArea 与当前图统计
  - 缺陷页局部背景（BackgroundRadius，0–16，默认 2，0 为关闭）：每个材质有"使用局部背景"开关，默认只对金属开启。0 = 关闭，区间直接作用于原始 GV；大于 0 时，勾选了该开关的材质先减去同材质 (2r+1)² 邻域的中位数（局部背景）再套用区间，金属这类亮度不均匀的材质不会整块报成巨大缺陷，过检时表现为零散的小点；代价是中位数会跟随有清晰边缘的平台，只检出比窗口小的局部异常，大块平整的缺陷会被当作背景（例如 SR 上画的 7×7、+80 的方块完全检不出），所以 SR 等亮度单峰的材质默认保持全局区间。统计表里的标准差与范围是扣除局部背景后的值，缺陷的峰值/均值 GV 仍是原始灰度；修改半径或开关都会重新学习区间
  - 缺陷页检出原理：只看测试图的亮度，按设计材质图逐材质判断——某材质的像素落在可接受区间 [Low, High] 之外就被标记（高于 High 为过亮，低于 Low 为过暗）；良品亮度越界也会被标记（过检），区间过宽则会漏检。缺陷是相互接触（8 连通）的被标记像素组成的连通块：判定逐像素进行，不使用平均值，不做膨胀或合并；Size 是一个缺陷至少需要的连续被标记像素数（例如 High=100、Size=2 时，105、106 会被检出，105、99、102 因为中间的 99 未被标记而不连续，不会被检出），MinArea 是连通块像素数的额外下限（实际阈值取 Size 与 MinArea 中较大者，默认 1）；过亮/过暗与不同材质之间不会合并。区间由良品样本学习得到：首次显示某型号/通道时（或按"重新学习区间"）渲染一张不含不良的良品样本（噪声种子不同），每个启用材质取 Low/High = 均值 ∓ k·σ；改变光照不会自动重学，因此过检/漏检会显现出来
  - 缺陷页边缘忽略（Margine）：与不同材质的像素的切比雪夫距离不超过"边缘忽略"（0–64 像素，默认 6）的像素会被忽略——不计入逐材质统计、不参与学习、永不被标记、探查时也不统计。报告里的"被忽略的边缘像素"与探查里的"框内被边缘忽略的像素"给出被忽略的数量。原因：参考型号的 SR 层约有 8000 个亮度 28–61 的像素（SR 均值 15），它们是 SR/Metal 交界处被模糊的过渡像素；没有边缘忽略时良品会报出 139 个过检，设为 6 后只剩 11 个（10 个真实 + 1 个）。自测：`edge-margin-off` 139 个缺陷，`edge-margin-on` 11 个
  - 缺陷页直接输入数值：F1 窗口里的每个数值参数（学习系数、边缘忽略、局部背景半径、Low / High、Size、最小面积、小格尺寸、各规则的偏移量与 Size）都是"滑块 + 输入框"：可以拖动滑块，也可以在滑块右侧的小输入框里直接键入数值，键入后立即生效（超出范围的值被限制在该参数的范围内）。
  - 缺陷页小格规则（Offset 1 绝对值 / Offset 2 百分比；规格见 [INSPECT_RULES.md](INSPECT_RULES.md)）：除了接受区间 [Low, High]，每个材质还有两条相对"小格平均"的规则。图像被切成 `小格尺寸 × 小格尺寸`（默认 400 × 400 像素，16–4096）的小格，某材质的每个有效像素与"它所在小格内同材质有效像素的平均 GV"比较：**Offset 1（绝对值）**——比平均亮超过"亮偏移"（GV）或暗超过"暗偏移"（GV）即被标记；**Offset 2（百分比）**——比平均亮超过 "亮偏移 %" 或暗超过 "暗偏移 %"（相对平均的百分比）即被标记。每条规则的亮 / 暗各有自己的偏移量和最小连续像素数，因此每个材质共 2 规则 × 2 极性 × （偏移量 + Size）= 8 个新参数；偏移量为 0 表示该极性不检查。每条规则、每个极性各自按 8 连通和自己的 Size 过滤，通过的像素合并后成为缺陷，结果表新增"规则"列（区间 / 绝对值 / 百分比，可同时出现多个）。材质里还有"使用接受区间"开关（关掉后只靠小格规则）；窗口上方有全局的"小格尺寸"和"平滑"（在小格中心之间线性插值，避免小格边界处的阶跃）。不足半格的尾巴并入最后一格；有效像素少于 64 的小格借用周围 3×3 小格或整图的材质平均。所有小格规则默认关闭——在亮度本来就不均匀的材质上（例如金属）它们会标记很多像素，需要用户按材质自己打开并调到合适的偏移量。
  - 缺陷页结果：检出数、因 Size/MinArea 滤除的连通块数、越界像素总数；逐材质统计表（材质、像素、均值、标准差、最小、最大、区间、过亮、过暗）；缺陷表（材质、极性、面积、宽×高、峰值 GV、超出量、均值 GV，最多显示面积最大的前 500 个，点击某行视图居中）。视图上的缺陷框：橙色为过亮、蓝色为过暗，并带"材质 面积"标签
  - 缺陷页探查：拖框后按材质显示像素数、均值、最小/最大、区间与过亮/过暗计数，并给出通俗解释（全部落在区间内 → 没有标记，区间过宽会漏检；有标记但连续像素数不足 Size/MinArea → 被丢弃；否则给出框内缺陷数）
  - 缺陷页的标准图 / 差异图只是仿真的显示辅助，检出本身从不接收标准图
- 菜单栏：文件（管理员登录… / 注销、机台配置…、重新扫描型号、退出）、视图（主题、语言、适应窗口）、帮助（关于…）
- 工具栏：机台下拉框 + `…` 按钮（管理员）、型号下拉框、加载状态、右端的用户名与登录 / 注销按钮
- 页签：教学程序的操作员界面为对位 / 检测，管理员界面为对位 / 对位试验台 / 缺陷检出；工作室为光照与 GV / 缺陷合成页（登录后），切换均不重载

## 相机合成工作室（camera-gui.exe）

`camera-gui.exe` 是 `camera.exe` 的 GUI 前端，把原始 MEDIAN 图像处理成合成抓拍，窗口标题为 "Color AFVI Camera Studio"。它包含「光照与 GV」页（亮度调节、GV 测量）与「缺陷合成」页（渲染通道、虚拟良品、笔刷、画框工具、颜色、幅度、轮廓、随机不良、传感器噪声、测试图/标准图/差异图、选择面板与浮动编辑器、可见的笔画轮廓）；它从不运行检出。

右侧「输出」栏把当前场景保存成抓拍：

- 输出文件夹：默认 exe 同级的 `captures/<型号 id>`（`/` 替换为 `-`）。
- 通道复选框 Red/Green/Blue：至少选择一个。
- 「同时输出良品样本」：额外写出 `red-good.png` 等不含不良的良品样本，供教学程序学习区间。
- 「仅输出描述文件」：只写 `snap.json.gz`（几 KB），任何消费者都能据此确定性地重新合成完全相同的像素。
- 「错位与翘起」分组（缺陷合成页左侧，成像噪声之后）：平移、旋转、缩放、翘起 X/Y（透视倾斜）、弯曲幅度与波长、剪切和五个预设（无 / 轻微错位 / 严重错位 / 翘起 / 典型错位（相机默认））；整块产品（含缺陷）一起移动，传感器噪声在其后叠加，良品样本保持标称位置。生效时视图里的绘制与选择停用，场景摘要显示该参数，保存的 `snap.json` 带 `recipe.warp`，实时联机也随之更新。
- 「保存抓拍」：运行 `camera.exe`（在 exe 同级或由 `AFVI_CAMERA_EXE` 指定）并写出 `snap.json` 与各通道 PNG；下方显示场景摘要与最近一次保存。

交接给教学程序：**默认不需要保存文件**——同时打开 camera-gui.exe 与 teach-imgui.exe（先后顺序无关），在工作室里画缺陷，教学程序的缺陷检出页约 0.1 秒后就显示并检出它（见下面的「实时联机」）。「保存抓拍」仍可用，用来留一份文件；教学程序也可以自己把看到的画面保存下来。

「输出」栏里的「实时联机」分组显示监听地址、已连接的教学程序和当前修订；端口被占用时显示原因，程序照常运行（用 `-link` 换一个端口，教学程序也要用同一个地址）。

「输出」栏里还有「场景文件（XML）」分组：把光照混合、虚拟良品、噪声、错位与翘起、**全部**缺陷笔画（含被禁用的和自动生成的默认小缺陷）以及笔刷、随机缺陷、输出栏等界面设置高密度地存成一个 `scenario.xml`（默认 `captures/<型号 id>/scenario.xml`，`.xml.gz` 为压缩版；`AFVI_CAPTURES` 可改变 `captures` 的位置）。「保存场景 / 载入场景」按钮手动读写；勾选"自动保存，并在载入型号时自动恢复"（默认）时，改动约 0.5 秒后自动写入，下次载入同一型号先恢复上次的场景。型号或图像尺寸不一致的场景会被拒绝，面板保持不变。保存抓拍时也会在抓拍文件夹里放一份 `scenario.xml`。教学程序用「相机抓拍 → 路径 → 载入」读取这个文件（或含它的文件夹），**不需要启动 `camera.exe`**：缺少的图像由教学程序在进程内按配方渲染，与 `camera.exe` 逐字节一致。格式见 [SCENARIO.md](SCENARIO.md)。

## 实时联机

两个 GUI 通过本机端口通信（协议与格式见 [LINK.md](LINK.md)）。教学程序缺陷页左侧的「实时联机」分组：

- 连接状态：已连接工作室（程序名与 PID）或"等待相机工作室…"，每 2 秒自动重连，工作室中途重启也会接上。
- 复选框 **跟随相机工作室**（默认勾选）：工作室每发布一个新修订就把它作为测试图并重新检出；只取像素，不同步工作室的光照、虚拟良品或笔画。已学到的区间保留（所以改光照后能看到过检 / 漏检），要用新场景的良品样本重新学习就点 F1 里的「重新学习区间」。
- 测试图来源：工作室（实时，修订号）、抓拍文件夹或本程序的本地仿真；标准图 / 差异图视图会按需向工作室再取一张干净渲染。
- 工作室打开的型号与教学程序当前型号不同时不跟随，给出「切换到该型号」按钮。
- 「抓拍」「载入」或勾选「使用相机抓拍图像」会停止跟随，免得你选的文件被实时画面替换；取消勾选「跟随相机工作室」回到本地仿真。
- 连接中断时保留最后一张图。

### 保存与载入

「相机抓拍」分组里的路径框默认是 `captures\<型号 id>`（exe 同级，与工作室输出栏相同；改过之后不再自动变）：

- **保存**：写入 `snap.json`、三个通道的测试图与良品图，以及 `inspect.json`（每个通道的学习区间、尺寸、最小面积、边缘忽略、局部背景等检出参数）。
- **载入**：读入该文件夹并恢复其中的 `inspect.json`（型号与尺寸相符时），已学习的区间不再重新学习。
- F1 检出参数窗口里的「保存检出参数 / 载入检出参数」只读写 `inspect.json`。

## 手动控制（检出 / 载入图像）

教学程序缺陷页左侧面板里，紧跟相机通道分组之后是「手动控制」分组：复选框「手动模式（改动后不自动检出）」默认关闭；打开后换通道、改光照、改参数或换图只刷新测试图并清除旧结果，按「检出」（F5）才学习并检出。「载入图像…」打开 Windows 打开文件对话框，载入 PNG/JPEG/BMP/TIFF（转成 8 位灰度，尺寸必须与型号一致）作为测试图；它取代实时联机、相机抓拍与本地仿真，并停止「跟随相机工作室」，按「改用仿真」或重新 Snap / 载入抓拍即可换回。载入的图像没有良品样本，学习（首次检出或「重新学习区间」）用它自己；标准图 / 差异图视图显示测试图；「保存」此时只写 `inspect.json`。详见 [MANUAL.md](MANUAL.md)。

## 相机抓拍（Snap）

缺陷页左侧面板的"相机抓拍"分组（紧跟渲染通道分组之后）把测试图换成独立相机程序 `camera.exe` 的"实拍"图：

- 勾选"使用相机抓拍图像"后，按钮 **Snap** 把当前场景（启用的笔画、虚拟良品、光照、噪声）写成描述文件，运行 `camera.exe`，读回 PNG 并检出；文本框 + **Load** 读取已有抓拍文件夹或描述文件，并导入其中的笔画与噪声。
- 抓拍后又编辑过（改笔画、光照、噪声等）会显示过期警告：需要重新 Snap，在此之前仍显示已抓拍的图像。
- 切换渲染通道时按需向 `camera.exe` 索取缺失的通道；取消勾选即回到进程内仿真。
- 标准图 / 差异图仍是本地干净渲染；检出依旧只接收测试图与设计材质图。
- 临时抓拍文件夹在被替换、重置或退出时删除。

手工运行相机程序（Linux 或 Windows 均可，纯 Go）：

```bash
bin/camera -ref reference -list
bin/camera -ref reference -model FM1/25fbo015-15 -channels red,green,blue -good -out capture/
bin/camera -in capture/snap.json -out capture2/ -channels blue
bin/camera -info capture/snap.json
# 错位与翘起：平移 8/-5 像素、转 0.3°、一侧翘起并带轻微弯曲
bin/camera -ref reference -model FM1/25fbo015-15 -dx 8 -dy -5 -rot 0.3 -tilt-x 0.01 -bend 6 -out capture/
```

直接运行 `bin/camera`（不带 `-model` 与 `-in`）会使用当前机台的第一个型号，渲染红色通道并写入 `snap-out/`；它是命令行程序，在资源管理器里双击会一闪而过，请在终端里运行。

错位与翘起标志：`-dx -dy`（像素）、`-rot`（度，±15）、`-scale`（0.8–1.2）、`-shear-x -shear-y`（±0.2）、`-tilt-x -tilt-y`（透视倾斜，±0.5，绝对值之和 < 0.9）、`-bend`（像素，±200）、`-bend-wave`（像素，≥ 50，默认 2000）。默认场景自带轻微错位（平移 14 / -10 像素、旋转 0.3°，`core.DefaultCaptureWarp()`）；`-aligned` 让内置默认场景原地渲染，和 `-in` 一起给出时忽略。只有显式给出的标志才改写配方，因此可以与 `-in` 配合；超出范围退出码为 2。整块产品（含缺陷）一起变形，传感器噪声在其后叠加，良品样本保持标称位置；描述文件的 `recipe.warp` 记录这些参数（没有错位时该字段不出现）。检出仍只看设计材质图，带错位的抓拍要先对齐。

## 已知限制

- 纹理固定线性过滤，高倍放大像素会被插值。
- 60 fps 持续重绘（空闲约占单核 3.4%）。
- 字体取自 `C:\Windows\Fonts`（tahoma / msyh / malgun），仅 Windows。
- 未做高 DPI 缩放适配。
- 检出是教学用的简化亮度区间算法（Metal / SR 各一个区间；真实产品的 Space、Open 等分层与 Margine、Offset 等机台参数未模拟），成像噪声也是近似。
- 检出的边缘忽略（Margine）是单一全局像素数；虚拟良品是统计意义上的非均匀（多尺度噪声 + 颗粒），不模拟真实的划痕、氧化、批次差异；默认不良只放在 SR 内部亮点；选择工具只选 GV 笔画（异物/污染笔画不可选）。
- 自测的鼠标交互在视图层注入，不经过 GLFW 真实输入。
