# AFVI Color Master Teach - 原生应用版本

Go + Dear ImGui 原生实现的 AFVI 彩色检查机教学桌面软件。

## 项目概述

本项目是 Color AFVI Master Teach 的原生 Windows 应用实现，使用 Go 语言和 Dear ImGui 构建，取代了基于 WebView2 的方案。同一个模块构建两个 GUI 程序与一个命令行相机程序：

- **teach-imgui.exe**（教学程序）：默认以**操作员**身份启动，只显示引导式的「对位」与「检测」两页；在「文件 ▸ 管理员登录…」用内置账号登录后是原来的完整工程界面（对位、对位试验台、缺陷检出页：相机通道、相机抓拍来源、F1 检出参数、学习区间、结果与探查）。两套界面都没有绘制工具、没有光照页，也从不画出模拟笔画轮廓（那是答案）。角色、页面与强制对位流程见 [docs/ROLES.md](docs/ROLES.md)。
- **camera-gui.exe**（相机合成工作室，窗口标题 "Color AFVI Camera Studio"）：camera.exe 的 GUI 前端，把原始 MEDIAN 图像处理成合成抓拍；它是管理员工具，启动时锁定在登录窗口之后。包含「光照与 GV」页与「缺陷合成」页（渲染通道、虚拟良品、笔刷、画框工具、颜色、幅度、轮廓、随机不良、传感器噪声、测试图/标准图/差异图、选择面板与浮动编辑器、可见的笔画轮廓）；它从不运行检出，右侧「输出」栏把当前场景保存成抓拍。
- **camera.exe**（命令行）：相机模拟程序，两个 GUI 都以子进程方式调用它。

两个 GUI 之间通过本机端口**实时联机**（协议见 [docs/LINK.md](docs/LINK.md)）：在工作室里画缺陷，教学程序约 0.1 秒后就在测试图里看到并检出，不需要保存任何图片；需要留存时由教学程序保存图片和检出参数（`inspect.json`），下次用「载入」读回。默认地址 `127.0.0.1:47631`，`-link` 修改，`-link off` 关闭。

## 快速开始

### 前置要求

**开发环境（WSL2/Linux）：**
- Go 1.27+
- MinGW-w64 交叉编译工具链

**运行环境（Windows）：**
- Windows 10+
- reference 目录（包含机台测试数据）

### 安装依赖

```bash
# 安装 MinGW-w64
sudo apt-get update
sudo apt-get install -y mingw-w64

# 验证安装
x86_64-w64-mingw32-gcc --version
```

### 构建

```bash
# 一键构建：检查与测试 -> teach-imgui、camera-gui、camera -> 安装包
./scripts/build-wsl.sh
./scripts/build-wsl.sh --no-installer   # 只构建三个程序，不生成安装包
```

输出为 `bin/teach-imgui.exe`、`bin/camera-gui.exe`、`bin/camera.exe`，以及 `dist/AFVI-Teach-Setup-<版本>.exe`（一键构建的最后一步，见下）。Windows 原生用 `.\scripts\build.ps1`（同样以安装包收尾，`-NoInstaller` 跳过）。

详细构建说明见 [docs/BUILD.md](docs/BUILD.md)。

### 安装包（setup.exe）

```bash
./scripts/build-wsl.sh                         # 一键构建已包含安装包：dist/AFVI-Teach-Setup-<版本>.exe（约 14 MB）
./scripts/build-wsl.sh --reference reference   # 连同机台数据一起打包（默认不含）
./scripts/package-wsl.sh --no-build            # 只重新打包 bin/ 里现有的程序
```

一个自解压安装程序（纯 Go，不需要 NSIS / Inno Setup），把教学程序、相机工作室、`camera.exe`、文档与机台配置示例装到 `%LOCALAPPDATA%\Programs\AFVI Teach`（每用户安装，不需要管理员权限），并创建开始菜单 / 桌面快捷方式、命令行入口（可选加入 PATH）和“应用和功能”里的卸载项。图形向导或 `-silent` 静默安装，`uninstall.exe` 卸载并默认保留 `afvi.toml` 与 `captures`。Windows 原生用 `scripts\package.ps1`。参数与细节见 [docs/BUILD.md](docs/BUILD.md)。

推送之后的构建和发布由一台 Linux 构建服务器自动完成，本机只做开发和测试：服务器每分钟检查 GitHub，`main` 有新提交就跑同一个一键构建脚本并覆盖滚动预发布 `nightly`，推送 `v*` 的 tag（`git tag v1.0.0 && git push origin v1.0.0`）就发布同名 Release，附安装包和 `SHA256SUMS.txt`。GitHub Actions 里的 `release.yml` 只保留手动试跑（只产出 artifact）。安装、token 与服务器上的目录布局见 [docs/SERVER_CI.md](docs/SERVER_CI.md)，概览见 [docs/BUILD.md](docs/BUILD.md)。

### 运行（Windows 环境）

```powershell
# 基本运行（教学程序）
.\bin\teach-imgui.exe

# 相机合成工作室
.\bin\camera-gui.exe

# 指定参数（两个 GUI 通用，-fontsize 为界面字号 10–28，默认 16）
.\bin\teach-imgui.exe -ref C:\path\to\reference -theme dark -lang zh -fontsize 16

# 指定机台配置文件
.\bin\teach-imgui.exe -config afvi.toml -machine AFVI-01

# 实时联机：先后顺序无关，各开一个窗口即可；换端口或关闭联机（两个程序要用同一个地址）
.\bin\camera-gui.exe -link 127.0.0.1:47700
.\bin\teach-imgui.exe -link 127.0.0.1:47700
.\bin\teach-imgui.exe -link off

# 启动时打开特定型号
.\bin\teach-imgui.exe -model FM1/25fbo015-15

# 自测模式
.\bin\teach-imgui.exe -selftest -out selftest-output
```

界面采用经典 Win32（"Windows Classic"）外观：3D 立体边框、灰色面板、深蓝渐变对话框标题栏、属性表风格页签，以及菜单栏、工具栏和多窗格状态栏。默认主题为经典浅灰（`light`），深色主题（`dark`）沿用同一套立体边框方案。机台信息（名称、地址、FM1/FM2/BM 数据根目录）保存在 `afvi.toml` 中，可通过「文件 ▸ 机台配置…」或工具栏的 `…` 按钮编辑。

## 功能特性

- **教学程序（teach-imgui.exe）**
  - **操作员 / 管理员两种界面**：教学程序默认是操作员界面（「对位」与「检测」两页，只有大按钮与判定），「文件 ▸ 管理员登录…」（内置 `admin` / `1`）切到完整工程界面，「注销」回到操作员；页面默认拒绝，隐藏页既不能切换也不会绘制，机台配置、切换机台与重新扫描对操作员无效（详见 [docs/ROLES.md](docs/ROLES.md)）
  - **强制对位**：先在产品的设计假想图上确认 ROI 框（机台 ROI 为起点），按「确定对位」后才允许检测；每张抓拍先按这些 ROI 对齐成全分辨率的设计网格图（边缘复制、无黑边），再交给检出；改 ROI 或换型号都会取消对位
  - **默认错位的相机**：`camera.exe` 与教学程序的内置仿真默认带平移 (14, -10) 像素、旋转 0.3° 的错位，用来模拟真实上料；`camera.exe -aligned` 原地渲染默认场景，工作室的错位预设新增「典型错位（相机默认）」
  - **手动控制**：缺陷页的「手动模式」「检出（F5）」「载入图像…」，由用户决定何时检出、检出哪张图（详见 [docs/MANUAL.md](docs/MANUAL.md)）
  - **应用图标**：两个 GUI 都有 Win32 经典风格的图标，由 `internal/appicon` 渲染、`go run ./cmd/mkicon` 生成（详见 [docs/ICON.md](docs/ICON.md)）
  - **对位页面**：先在产品的设计假想图上确认 ROI 框（强制对位），检测前每张抓拍都先对齐；管理员另有原来的对位试验台（合成错位实验）
  - **缺陷检出页面**：相机通道、相机抓拍来源、F1 检出参数、学习区间、结果与探查；无绘制工具，也不显示模拟笔画轮廓
- **相机合成工作室（camera-gui.exe）**
  - **光照与 GV 页面**：亮度调节、GV 测量
  - **缺陷合成页面**：缺陷标注（点/线/块/异物/污染）、虚拟良品、笔刷与画框工具、颜色、随机不良、传感器噪声、测试图/标准图/差异图、选择面板与浮动编辑器、可见的笔画轮廓
  - **输出栏**：把当前场景保存成抓拍（输出文件夹、通道、良品样本、仅描述文件），交给教学程序用「相机抓拍」载入
- **虚拟良品与默认不良**：加载型号时把确定性的表面不均匀烘焙进光照场景，所有页面都渲染"真实"良品；缺陷页自动加入约 10 个肉眼几乎不可见的默认亮点
- **悬浮工具面板与专注模式**：视图右侧的 Photoshop 风格工具面板（点选 / 矩形框 / 椭圆框 / 多边形框 / 专注），F11 或视图菜单可隐藏两侧面板放大中央图像
- **选择与调参**：用悬浮面板选中已画的不良，在浮动窗口中批量调整幅度、半径、柔和度、颗粒、边缘轮廓与启用状态，并显示哪些不良已被 Inspect 检出
- **实时联机**：工作室（服务端）与教学程序（客户端）经本机端口对等通信，工作室里的每次修改约 0.1 秒后出现在教学程序的测试图里，教学程序据此检出，全程没有图片文件；教学程序可随时「保存」当前画面（三个通道的测试图与良品图）和检出参数，下次「载入」；路径默认 `captures\<型号 id>`，两个程序相同
- **保存检出参数**：每个通道的学习区间、尺寸、最小面积、边缘忽略、局部背景等存成 `inspect.json`（与抓拍同一文件夹，也可在 F1 窗口单独保存 / 载入），载入抓拍时自动恢复
- **小格规则与直接输入**：除接受区间外，每个材质新增两条相对 400×400 小格平均 GV 的检出规则——Offset 1 绝对值、Offset 2 百分比，亮 / 暗各有偏移量和最小连续像素数（每材质共 8 个新参数，默认关闭，规格见 [docs/INSPECT_RULES.md](docs/INSPECT_RULES.md)）；F1 窗口里所有数值参数除了拖动滑块，也可以在旁边的输入框里直接键入
- **场景文件（XML）**：相机工作室把光照混合、虚拟良品、噪声、错位翘起、全部缺陷笔画（含禁用 / 自动的）和界面设置存成 `scenario.xml`，自动保存、载入型号时自动恢复；教学程序不启动 `camera.exe` 也能读取并在进程内渲染（逐字节一致），格式见 [docs/SCENARIO.md](docs/SCENARIO.md)
- **相机模拟与抓拍（Snap）**：独立的 `camera.exe`（纯 Go，无 cgo）把完美的 MEDIAN 渲染成有缺陷的"实拍"图，缺陷页可勾选"使用相机抓拍图像"后 Snap（把当前场景写成描述文件、调用 `camera.exe`、读回 PNG 并检出）或 Load（读入已有抓拍并导入其笔画与噪声）；抓拍与进程内渲染逐字节一致，检出依旧只看测试图与设计材质图
- **多语言支持**：中文、英文、韩文
- **主题切换**：经典浅灰 / 深色主题运行时切换（视图菜单）
- **经典 Win32 外观**：3D 立体边框、菜单栏、工具栏、多窗格状态栏
- **机台配置**：`afvi.toml` 记录每台机台的名称、地址与 FM1/FM2/BM 数据根目录，可在「文件 ▸ 机台配置…」对话框中增删改并检查路径
- **性能优化**：
  - 加载型号：~300 ms
  - 光照渲染：~29 ms
  - 对齐计算：~150 ms
  - UI 帧率：60 fps

## 操作说明

### 通用操作

- **滚轮**：缩放（以光标为中心）
- **Shift + 鼠标左键点击**：放大（×1.5，以光标为中心）；**Shift + 鼠标右键点击**：缩小（÷1.5，以光标为中心）
- **中键/右键拖动**：平移画布
- **双击**：适应窗口（画框工具绘制过程中不会触发）
- **悬浮工具面板**：视图右侧的 Photoshop 风格工具面板，含点选、矩形框、椭圆框、多边形框与专注按钮；当前页面不支持的工具会变灰并忽略点击，再次点击已激活的工具即回到平移
- **专注模式**：点击面板上的专注按钮、按 F11 或选择「视图 ▸ 专注模式」，隐藏左右两侧面板让中央图像铺满窗口；F1 参数窗口与选中的不良窗口仍可正常使用，双击适应窗口的行为不变
- **菜单栏**：文件（管理员登录… / 注销、机台配置…、重新扫描型号、退出）、视图（主题、语言、适应窗口、专注模式）、帮助（关于…）
- **工具栏**：机台下拉框 + `…` 按钮（管理员）、型号下拉框、加载状态、右端的用户名与登录 / 注销按钮

### 页面操作

**光照与 GV 页（camera-gui.exe）**：
- 左侧滑块：调节亮度
- 左键拖框：测量 GV
- 悬浮工具面板：只支持矩形框（GV 测量框，始终激活）

**对位试验台（teach-imgui.exe，管理员）**：
- 左键：新建 ROI/遮挡
- 选择移动：拖动 ROI
- Delete：删除选中的 ROI
- 悬浮工具面板：点选（选择/移动 ROI）与矩形框（新建 ROI / 遮挡）
- 视图默认是**叠加图**（模板红色、扭曲后的输入青色，对不齐处出现红青色边）；也可切到模板、输入、差分。视图里每个 ROI 画出：设计位置（灰色虚线）、真值位置（青色虚线，即扭曲参数把它实际移到的地方）、对齐结果（实线，拟合变换作用到该 ROI 的位置，颜色 = 真值误差，绿 ≤ OK 阈值、黄居中、红 > NG 阈值，旁边标 Δ 像素）、匹配点（绿点定位成功、红点失败）和从真值到对齐结果的向量；偏移参数一拉，图上立刻看得到，不必先运行
- 「模板图」下拉选择 ROI 模板的来源：**设计假想图**（默认）只由设计的 Metal/SR/Open 材质层生成——每个像素按所属材质填 MEDIAN 的均值、面积降采样、模糊 4 个全分辨率像素（`core.DesignBlurPx`），再用一张 6×5 网格 + RANSAC 相似变换把它一次性配准到 MEDIAN 上（设计层与实拍图通常差几像素，需要挪一下才重合），没有真实纹理也没有传感器噪声，因此放在无特征处的 ROI 不再"随便对上"（`core.DesignTemplate`）；**与源图相同（旧）** 则模板与输入是同一张图，任何 ROI 都以 NCC ≈ 0.99 匹配，正是掩盖问题的旧行为。输入始终是扭曲后的真实图；选「设计假想图」时下拉下方显示配准的位移
- **对齐后视图**（视图下拉的「对齐后（算法结果）」「对齐后叠加」「对齐后差异」）：把输入图按**算法自己拟合出的相似变换**重采样到模板网格（`core.RealignInput`，只用输入图和 `report.Fit`，不用设定的错位参数，也不是把扭曲还原），看对齐到底对不对。没有数据的边缘在对齐后图里是黑色、差异图里是蓝色，遮挡区不参与比较；叠加图越灰、差异图越暗说明越重合。这些视图只对产生该拟合的那张输入图有效：改了扭曲参数或遮挡后输入图重新生成，旧拟合不会套到新图上，要重新运行。判定区另有两项独立于 ROI 和真值的核对：「全图灰度差 对齐前→后」（有数据的像素上 |原图 − 图像| 的平均；原图 = 扭曲前的真实图，选「与源图相同」时就是模板，选「设计假想图」时不用没有纹理的假想图）与「对齐后局部残余位移 最大 / 均方根」（`core.CheckRealigned`：把原图（同上，不是假想图）切成约 20 个窗口，在对齐后的图里重新匹配，量出每个窗口还差多少，颜色按 OK/NG 阈值）。ROI 残差只反映 ROI 处，而相似变换由几个点拟合，离 ROI 越远误差越大，所以"判 OK 但看起来还是偏"时这一项更接近眼睛看到的；按钮「放大到最大残余处」缩放到 4 倍并定位到差得最多的窗口，视图里该窗口也画出方框和数值
- 扭曲参数按用途分组：「错位（位置）」= 预设按钮（无 / 轻微错位 / 严重错位 / 翘起 / 典型错位（相机默认））+ tx、ty、旋转、缩放；「翘起与形变」= 翘起 X/Y（透视倾斜）、弯曲幅度与波长、剪切 X/Y；「成像（光度）」（默认折叠）= 模糊、噪声、增益、偏置、渐变
- 右侧判定区：大号 OK / MANUAL / NG 横幅；「与真值核对」一行说明判定是否正确（判定正确 / 漏判：真值已超过 OK 阈值却判 OK / 误判：真值在 OK 阈值内却判 NG / 偏严 / 保守）；「设定 / 测得 / 差」表（中心位移 X、Y、旋转、缩放；位移差按 OK/NG 阈值着色）；残差 RMS 与阈值；各 ROI 的 NCC、唯一性、残差、匹配误差（该 ROI 自己匹配到的位置与真实位置的距离）、对齐误差（整体拟合把该 ROI 放到的位置与真实位置的距离，即机器实际使用的；两列都按 OK/NG 阈值着色）与状态（内点 / 外点 / 失败原因）；外点就是匹配误差大而对齐误差小的 ROI。表下方的「逐个 ROI 诊断」借助真值说明外点或未定位的原因（真实位置的窗口伸出图像多少、被遮挡盖住多少），判定原因也点名具体的 ROI 和数值。所有长度都以全分辨率像素显示，阈值也按工作分辨率换算成同一单位。含剪切、翘起或弯曲时相似变换无法完全描述，真值误差里包含这部分模型误差，界面会提示
- 参数改动后若没有重新运行，判定区顶部显示"参数已改动"提醒；正在计算时显示"正在重新计算"。是否过期按报告所用的输入（扭曲、遮挡、ROI、匹配参数、源图）与当前输入逐项比较，所以长时间运行（金字塔 1 约 30 s）结束时不会把运行期间的新改动当成已处理
- 匹配参数：搜索半径、金字塔、最小 NCC、最小唯一性、**最小重叠**、RANSAC 阈值、OK/NG 残差。最小重叠（默认 0.9）：机台 ROI 贴着图像角落，图像移动后它的真实位置会伸出图像，窗口在图内的比例不低于该值时只用图内部分计算 NCC，贴边 ROI 因此也能跟上轻微错位；1 = 窗口必须完整在图内（TS 版的行为，贴边 ROI 会被截在边界上、被判外点而转人工）。金字塔 1 配大搜索半径每次要算几十秒，界面按 `core.MatchCost` 粗估并提醒

**缺陷合成页（camera-gui.exe）**：
- 错位与翘起：左侧"错位与翘起"分组（成像噪声之后）设置产品在抓拍里的位置——平移 tx/ty、旋转、缩放；翘起 X/Y（透视倾斜，一侧被压缩另一侧被拉伸）、弯曲幅度与波长、剪切；五个预设（无 / 轻微错位 / 严重错位 / 翘起 / 典型错位（相机默认））。整块产品（含缺陷）一起移动，传感器噪声在其后叠加，良品样本保持标称位置；场景摘要与"最近一次保存"显示该参数。错位生效时视图里的绘制与选择停用（缺陷位置是产品自己的坐标系，请先编辑缺陷最后再设错位）
- 画缺陷：点/线/块/异物/污染
- 画框工具：矩形 / 椭圆 / 钢笔（类 Photoshop 钢笔：左键依次添加顶点，右键闭合多边形，Esc 取消，Backspace 撤销上一个顶点），可选择"亮/暗"极性；幅度、边缘轮廓、柔和度沿用左侧对应设置；画出的框成为不良（矩形/椭圆/多边形）并出现在笔画列表中
- 不良颜色：勾选"按颜色模拟"后，新画的不良带有 RGB 颜色（R、G、B 滑块 0–1 与七个预设：红、绿、蓝、白、黄、青、品红，列表中显示 RGB 后缀，视图中轮廓用该颜色显示）；渲染通道（Red/Green/Blue）下画面仍是黑白灰度，不良在某通道中的亮度变化 = 幅度 × 该通道的颜色分量（例如纯红不良只在 Red 通道可见，白色不良在三个通道都可见）；颜色设置只作用于之后新画的不良，随机批量生成也使用当前颜色
- 虚拟产品：左侧第二个分组（紧跟渲染通道之后）。真实板面不可能完全均匀——约 2 µm/像素下再好的表面工艺也有起伏，而加载的 MEDIAN 是多块良品的中值、过于平滑；加载型号时会把一份确定性的、带种子的空间相关变化（多尺度值噪声 + 逐像素颗粒，按材质各自的相对 σ）烘焙进光照场景，因此光照 / 对齐 / 缺陷三页渲染的都是略微不均匀的"真实"良品。控件：启用虚拟良品、纹理强度 0–3（变化幅度）、纹理种子 1–9999、相关长度倍率 0.25–4、换一块板（换随机种子）、恢复默认；任何改动都会即时重新烘焙场景。注意光照页自己的"纹理强度"滑块（0–1）会整体缩放纹理（含这份变化），把它设为 0 即得到理想均匀样品。默认种子 1、强度 1；参考型号上 SR 纹理的 RMS 变化约 0.118（相对值），5860×4020 生成一次约 0.25 s。`Scene.Stats`（逐材质 MEDIAN 统计）仍是原图的统计；Inspect 依旧只看测试图与设计材质图
- 默认不良：每次加载型号时缺陷页会自动加入约 10 个很小的亮点（数量 10、种子 7）：半径 1.5–3 像素、ΔGV 45–90（绝对）、高斯轮廓、柔和度 0.3，只放在 SR 内，且要求中心周围 `边缘忽略 + ceil(半径) + 3` 像素的整个窗口都是 SR（因此绝不会落在 Inspect 忽略的边缘带里）。它们是普通笔画（标记为 auto），出现在笔画列表中，可被选中、编辑、删除。参考型号实测（自测 `defaults-detected`）：10 条笔画，5860×4020 图中只有 175 个像素与干净渲染不同（肉眼不可见），自动学习后 10 个全部被 Inspect 检出，另有 1 个自然过检（良品并非绝对干净），学到的 SR 区间为 [2,30]。控件：默认不良数量 0–50、默认不良种子 1–9999、重新生成默认不良、移除默认不良，以及复选框"显示模拟笔画轮廓"（用至少 4 像素的标记画出笔画轮廓；关掉即可对学生隐藏答案，让他们必须通过 Inspect 找不良；选中高亮仍然可见）
- 选择与调参：悬浮工具面板的点选 / 矩形框 / 椭圆框 / 多边形框用于选择 GV 笔画。点选 = 单击选中最近的笔画（容差 6 屏幕像素，距离相同时取更小的那个；Ctrl+单击加入/移出选择；单击后继续拖动仍是平移）；矩形 / 椭圆 / 多边形框（拖动；多边形左键添加顶点、右键闭合；Esc 取消、Backspace 撤销上一个顶点）选中包围盒中心落在框内的所有笔画（Ctrl+拖动为加入而非替换；没有真正拖动的单击等同点选）。Delete 删除选中的笔画，Esc 清空选择。左侧面板武装的笔刷 / 画框放置工具优先，用完后选择工具恢复。选中的笔画以黄色高亮并保证最小屏幕尺寸（7 像素圆环 / 14 像素方框），适应窗口下 2 像素的不良也看得见；笔画列表给选中行加"● "前缀。浮动"选中的不良"窗口（选择非空时出现，`x` 清空选择）对全部选中笔画生效：更隐蔽（幅度 ×0.8、半径 ×0.9）与更清晰（幅度 ×1.25、半径 ×1.1）快捷按钮（目标模式的笔画保持目标值不变）、删除、取消选择、类型（亮/暗）、幅度模式（绝对/相对/目标）与跟随第一个选中笔画的数值滑块、半径、柔和度、颗粒、边缘轮廓、启用。窗口还显示"检出：N / M 个已被 Inspect 检出"——这只是 UI 层把报告框与笔画包围盒做比较的显示（`strokeDetected`），`internal/inspect` 依旧对笔画一无所知。自测 `select-edit`：ΔGV 80 的亮点被检出，执行"更隐蔽"（ΔGV 4、半径 1）后不再被检出，未选中的邻居仍被检出
- 检出参数：按 F1 唤出/关闭的浮动窗口（可拖动、可滚动，调整时检出结果实时刷新；Esc 或标题栏 × 关闭），左侧只保留"检出参数…（F1）"按钮与提示。窗口内按相机通道（Red/Green/Blue）各有一套参数：学习系数 k（0.5–12，默认 5）、"重新学习区间"与"恢复默认并重学"按钮、边缘忽略（像素）0–64（默认 6，三个通道共用，修改后会重新学习区间，下方给出说明与被忽略的像素数），以及 metal / sr / open / base 每个材质一节的启用、下限 Low、上限 High、连续像素数 Size、最小面积 MinArea 与当前图统计
- 检出原理：只看测试图的亮度，按设计材质图逐材质判断——某材质的像素落在可接受区间 [Low, High] 之外就被标记（高于 High 为过亮，低于 Low 为过暗）；良品亮度越界也会被标记（过检），区间过宽则会漏检。缺陷是相互接触（8 连通）的被标记像素组成的连通块：判定逐像素进行，不使用平均值，不做膨胀或合并；Size 是一个缺陷至少需要的连续被标记像素数（例如 High=100、Size=2 时，105、106 会被检出，105、99、102 因为中间的 99 未被标记而不连续，不会被检出），MinArea 是连通块像素数的额外下限（实际阈值取 Size 与 MinArea 中较大者，默认 1）；过亮/过暗与不同材质之间不会合并。区间由良品样本学习得到：首次显示某型号/通道时（或按"重新学习区间"）渲染一张不含不良的良品样本（噪声种子不同），每个启用材质取 Low/High = 均值 ∓ k·σ；改变光照不会自动重学，因此过检/漏检会显现出来
- 边缘忽略（Margine）：与不同材质的像素的切比雪夫距离不超过"边缘忽略"（0–64 像素，默认 6）的像素会被忽略——不计入逐材质统计、不参与学习、永不被标记、探查时也不统计。报告里的"被忽略的边缘像素"与探查里的"框内被边缘忽略的像素"给出被忽略的数量。原因：参考型号的 SR 层约有 8000 个亮度 28–61 的像素（SR 均值 15），它们是 SR/Metal 交界处被模糊的过渡像素；没有边缘忽略时良品会报出 139 个过检，设为 6 后只剩 11 个（10 个真实 + 1 个）。自测：`edge-margin-off` 139 个缺陷，`edge-margin-on` 11 个
- 局部背景（BackgroundRadius，默认 2，0 为关闭；每个材质有"使用局部背景"开关，默认只对金属开启）：金属的亮度是双峰的（暗约 36、亮约 165–225），单个全局区间下，只要上限低于亮条的亮度，整条亮条就被报成一个巨大缺陷（红光 375、金属上限 148：146 个缺陷、最大 16128 像素、45 万标记像素）。打开后，该材质的每个有效像素先减去同材质 (2r+1)² 邻域的中位数（局部背景，r 为半径），区间 [Low, High] 作用于扣除背景后的值 f = (v − 背景) + 背景均值（限制在 0–255，均值不变，统计表的标准差为残差的标准差，缺陷的峰值/均值 GV 仍是原始灰度）；同样的上限下只剩 36 个很小的缺陷（最大 19 像素、296 个标记像素），也就是"过检表现为密密麻麻的小点"，并且学到的金属区间不再是盲的（同一光照下 [0,255] → [50,202]）。代价：中位数会跟随有清晰边缘的平台，只检出比窗口小的局部异常，大块平整的缺陷会被当作背景（例如 SR 上画的 7×7、+80 的方块完全检不出），所以 SR 等亮度单峰的材质默认保持全局区间；半径越大越能保留大缺陷，但结构边缘处的残差也越大（半径 3 起金属已出现上千像素的分组），所以默认取 2。
- 结果：检出数、因 Size/MinArea 滤除的连通块数、越界像素总数；逐材质统计表（材质、像素、均值、标准差、最小、最大、区间、过亮、过暗）；缺陷表（材质、极性、面积、宽×高、峰值 GV、超出量、均值 GV，最多显示面积最大的前 500 个，点击某行视图居中）。视图上的缺陷框：橙色为过亮、蓝色为过暗，并带"材质 面积"标签
- 探查：拖框后按材质显示像素数、均值、最小/最大、区间与过亮/过暗计数，并给出通俗解释（全部落在区间内 → 没有标记，区间过宽会漏检；有标记但连续像素数不足 Size/MinArea → 被丢弃；否则给出框内缺陷数）
- 标准图 / 差异图只是仿真的显示辅助，检出本身从不接收标准图
- 输出栏：输出文件夹（默认 exe 同级的 `captures/<型号 id>`，`/` 替换为 `-`）、通道复选框 Red/Green/Blue、「同时输出良品样本」（`red-good.png` 等，供教学程序学习区间）、「仅输出描述文件」（写出 `snap.json.gz`，几 KB）与「保存抓拍」按钮；保存时运行 `camera.exe`（在 exe 同级或由 `AFVI_CAMERA_EXE` 指定）并写出 `snap.json` 与各通道 PNG，下方显示场景摘要与最近一次保存
- 实时联机分组（输出栏内）：监听地址、已连接的教学程序、当前修订；端口被占用时显示原因（程序照常运行）。实时联机不需要点「保存抓拍」

- 相机通道、相机抓拍来源（载入或 Snap 抓拍）、F1 检出参数、学习区间、结果与探查
- 没有绘制工具，也从不画出模拟笔画轮廓（那是答案）
- 测试图默认来自实时联机：工作室在运行时自动跟随它的场景（「实时联机」分组，复选框"跟随相机工作室"），显示来源与连接状态；型号不同时给出"切换到该型号"按钮；也可用「相机抓拍」载入或 Snap；既没有工作室也没有抓拍时使用内置默认场景（虚拟良品 + 约 10 个很小的不良）
- 「相机抓拍」分组的路径框默认是 `captures\<型号 id>`（与工作室输出栏相同）：「载入」读入并恢复该文件夹里的 `inspect.json`，「保存」写入 `snap.json`、三个通道的测试图与良品图和 `inspect.json`；F1 窗口里还有「保存检出参数 / 载入检出参数」

## 相机模拟（camera.exe）与抓拍（Snap）

`camera.exe` 是独立的相机模拟程序（源码 `cmd/camera/main.go`，逻辑在 `internal/camera`，纯 Go、`CGO_ENABLED=0`，Linux 与 Windows 都能构建运行）：它把完美的 MEDIAN 渲染成有缺陷的"实拍"图，教学应用通过"抓拍（Snap）"读取这份实拍。`camera-gui.exe` 是它的 GUI 前端：在工作室里画好场景后按「保存抓拍」，同样由 `camera.exe` 写出抓拍文件夹。两侧靠文件契约与进程边界解耦，互不依赖。

抓拍是一个文件夹：描述文件 `snap.json`（也可单独作为 `*.json` 或 gzip 压缩的 `*.json.gz` 读取；未知字段忽略；`version` 为 1）加上 8 位灰度 PNG `red.png`、`green.png`、`blue.png`（kind 为 `test`）与 `red-good.png` 等（kind 为 `good`，不含不良的良品样本，用于学习区间）。`snap.json` 携带全部元信息：`format`（`afvi-snap`）、`version`、`producer`、`created`（UTC）、`model`（id、host、model、side 以及 Metal/SR/Open/MEDIAN 各层的绝对路径）、`width`、`height`、`recipe`（`product` 虚拟良品选项、`light` 光照设置、`noise` 成像噪声、`defects` GV 不良笔画、`sceneStrokes`）与 `images`（通道、kind、文件、宽高、原始像素的 sha256，读取时校验）。用 `-mode recipe` 只写描述文件：只有几 KB（gzip 压缩后更小），任何消费者都能据此确定性地重新合成完全相同的像素。

命令行示例：

```bash
# 列出参考目录里的型号
bin/camera -ref reference -list

# 渲染一个型号的三个通道（含良品样本）
bin/camera -ref reference -model FM1/25fbo015-15 -channels red,green,blue -good -out capture/

# 只写描述文件（几 KB，可 gzip）
bin/camera -ref reference -model FM1/25fbo015-15 -mode recipe -out desc.json.gz

# 由描述文件重新渲染某个通道
bin/camera -in desc.json.gz -out capture/ -channels blue

# 查看抓拍信息
bin/camera -info capture/snap.json
```

不带 `-model` 与 `-in` 直接运行 `bin/camera` 时，使用当前机台的第一个型号（与教学应用一致），默认只渲染红色通道并写入 `snap-out/`（已被 Git 忽略）。`-channels` 接受 `red,green,blue` 或 `all`；`-count N -seed N -strength X -no-product -noise-read S -noise-shot G -noise-seed N` 调整默认场景，`-dx -dy -rot -scale -shear-x -shear-y -tilt-x -tilt-y -bend -bend-wave` 设置产品在抓拍里的错位与翘起（见下）（默认与教学应用一致：标称虚拟良品、红/绿/蓝三路光照 512、无成像噪声、10 个很小的亮点，种子 7，由应用与相机共用的 `core.DefaultTinyDefects` 生成）。`-in <snap.json|desc.json.gz|文件夹>` 重新渲染描述文件；不带 `-model` 时使用描述文件里记录的层路径；输出文件夹若已存有同一份 recipe 则保留原有图像。`-config/-machine/-ref` 与教学应用相同。退出码：0 成功、1 运行失败、2 用法错误。参考型号 25fbo015-15（5860×4020）实测：Windows 上渲染一个通道加良品样本约 4 s。

错位与翘起（相机参数）：`-dx/-dy`（像素，向右/向下为正）、`-rot`（度，±15）、`-scale`（0.8–1.2，绕图像中心）、`-shear-x/-shear-y`（±0.2）、`-tilt-x/-tilt-y`（透视倾斜，±0.5，两者绝对值之和 < 0.9：一侧被压缩另一侧被拉伸，像板子一边翘起）、`-bend`（弯曲幅度像素，±200）与 `-bend-wave`（波长像素，≥ 50，默认 2000）。例如 `bin/camera -ref reference -model FM1/25fbo015-15 -dx 8 -dy -5 -rot 0.3 -tilt-x 0.01 -bend 6 -out capture/`。只有命令行里显式给出的参数才改写配方，所以也能和 `-in` 配合（把一份描述换个位置重新渲染；全部归零则去掉 warp）；超出范围时退出码为 2，stderr 指明是 warp 参数。整块产品（含缺陷）一起移动：先渲染标准图和测试图，再整体变形，之后才叠加传感器噪声；良品样本是示教基准，始终在标称位置。描述文件 `snap.json` 的 `recipe.warp`（`tx ty thetaDeg scale shearX shearY tiltX tiltY bendAmplitude bendWavelength`）记录这些参数，没有错位时整个字段不出现，旧描述逐字节不变；`-info` 会多打印一行 `warp: ...`。检出只看设计材质图，所以带错位的抓拍要先做对齐，否则材质边缘会被当成缺陷（缺陷页在载入这类抓拍时给出提示）。几何实现是 `core.WarpParams`（新增 `TiltX/TiltY`，为 0 时与 TS 实现逐字节相同）与 `core.RenderDefectPairWarped`；应用内渲染、实时联机的渲染器与 `camera.exe` 走同一个函数，所以三者逐字节相同（自测 `studio-warp`）。

教学侧（缺陷页左侧面板"相机抓拍"分组，紧跟渲染通道分组之后）：复选框"使用相机抓拍图像"；按钮 Snap（把当前场景——启用的笔画、虚拟良品、光照、噪声——写成描述文件，运行 `camera.exe`，读回 PNG 并检出）；文本框 + Load（读取已有抓拍文件夹或描述文件，并导入其中的笔画与噪声）；抓拍元信息表格；抓拍过期时的警告（抓拍后又编辑过：需重新 Snap，在此之前仍显示已抓拍的图像）；切换通道时按需向 `camera.exe` 索取缺失的通道；取消勾选即回到进程内仿真。标准图 / 差异图仍是本地干净渲染。`camera.exe` 的查找顺序为环境变量 `AFVI_CAMERA_EXE` → 教学程序 exe 同级 → PATH。临时抓拍文件夹在被替换、重置或退出时删除。检出依旧只接收测试图与设计材质图。

实时联机（[docs/LINK.md](docs/LINK.md)）把同一份契约放在 `internal/link`：工作室发布 `snap.Meta` 描述（没有像素），教学程序按需拉取 8 位灰度帧（`test` 测试图、`good` 良品样本、`golden` 仅供标准图 / 差异图视图），帧与 `camera.exe` 用同一份描述写出的 PNG 逐字节相同；修订号过期的请求被拒绝，所以不会把旧图当新图。教学程序只取像素，不同步工作室的光照 / 虚拟良品 / 笔画；保存的抓拍文件夹与联机无关，没有工作室时照常载入。

解耦规则由测试守护：`internal/app` 从不导入 `internal/camera`；`internal/camera` 从不导入 `internal/inspect` 或 `internal/app`；`internal/core` 不导入 snap/model/camera/inspect 中的任何一个；`internal/snap` 只导入标准库与 `internal/core`；`internal/inspect` 保持只用标准库；`internal/link` 只导入标准库与 `internal/snap`，且只有 `internal/app` 里的联机文件（`live*.go`、`teach_save.go`）能导入它。`app` 包内把格式包导入为 `snapfmt`，因为该包已有一个名为 `snap` 的函数。

限制：只有缺陷页能使用抓拍（光照页与对位试验台仍在进程内渲染）；每次抓拍进程都会重新加载 TIFF 各层；自测截图需要未锁屏的 Windows 会话。

两个程序的自测步骤按程序过滤（`filterSteps`）：教学程序跑对齐与检出步骤，工作室跑光照与合成步骤，外加一个 `studio-save` 步骤（通过 `camera.exe` 写出 `<dir>\studio-capture` 并校验像素的 sha256）。两者都需要 `camera.exe` 与可执行文件放在一起，`native-metrics.json` 的 `errors` 必须为 null。

## 已知限制

- 纹理固定线性过滤，高倍放大时像素会被插值
- 60 fps 持续重绘
- 字体取自 `C:\Windows\Fonts`，仅支持 Windows
- 未适配高 DPI 缩放
- 检出是教学用的简化亮度区间算法（Metal / SR 各一个区间；真实产品的 Space、Open 等分层与 Margine、Offset 等机台参数未模拟），成像噪声也是近似
- 检出的边缘忽略（Margine）是单一全局像素数；虚拟良品是统计意义上的非均匀（多尺度噪声 + 颗粒），不模拟真实的划痕、氧化、批次差异；默认不良只放在 SR 内部亮点；选择工具只选 GV 笔画（异物/污染笔画不可选）

## 与 Tauri 版本的关系

本项目是独立的原生实现。原 Tauri + Svelte 5 版本保留在另一个仓库（DMT_AFVI_Color_Parameter_AutoParse），作为界面还原和规格说明的参考实现。

两个版本的核心算法保持一致，但实现技术栈不同：
- **原生版（本项目）**：Go + Dear ImGui，更快的启动速度和渲染性能
- **Tauri 版**：Rust + TypeScript + Svelte 5，更现代的 Web 技术栈
